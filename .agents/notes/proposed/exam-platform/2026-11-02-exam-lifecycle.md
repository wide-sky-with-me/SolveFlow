# 逐题拍摄与实时状态生命周期提案

日期：2026-11-02。状态：proposed。范围：客户端推进、补图、任务及WebSocket恢复。

## 背景

[总方案](2026-11-02-managed-exams.md)要求不能跳题，用户已选择答案返回后自动推进。补图可以回到历史模块，不能影响其他题和当前进度。

## 决定

### 顺序与版本

开始考试的事务冻结模板、模块、时间及展示策略，展开所有题位。场次分配的服务端时间为准，保存UTC时间并按配置时区展示；重叠分配需拒绝或管理员明确选择，不偷偷进入另一考试。

首拍仅允许当前模块最早未完成题位。HTTP上传完成不推进；原始结果和展示结果都提交成功后，CAS核对题位/版本/run，事务内推进拍摄游标并写事件。客户端收到后自动将拍摄目标设为下一题，固定答案区仍展示刚完成题的答案。上传、解析、解题失败或澄清均停留原题。学生可查看旧题，未来题禁拍；用户正在回看时只更新拍摄目标，不抢走当前阅读焦点。有效答案可推进，未通过核验单独警示，不以verified作为唯一推进条件。

重拍/补图必须携带题位ID、预期版本及幂等键，服务端创建新快照，取消或作废旧活动run；旧回调不得覆盖新版本。历史题重答只更新该题，不倒退/前进主游标。模块推进按每个题位完成一次计算，不按照片或run计数；全部完成才解锁下一模块。

模块时长先作模板参考，是否强制计时由场次冻结配置明确；时限结束记未完成，不伪造已答。窗口结束后拒绝新拍/补图，已在截止前接收的任务按冻结宽限策略收尾；超出宽限标中断。管理员重新开放或校正题位必须显式授权并审计，不能绕过未完成题无痕改进度。

### 事务和状态

场次状态与题目状态分离；题目再分拍摄、解题、核验和展示四条状态，出答案不等于核验通过。单题最多一个活动run；worker领取采用现有`FOR UPDATE SKIP LOCKED`＋租约/fencing，每次模型调用前持久记录派发。数据库事务不跨模型或对象网络请求。

只对确定未派发任务继续调度；调用开始但无终态的故障任务标中断，不因重启自动重做付费请求。显式重答新建run、保留旧版。断网仅断订阅，明确“停止”才持久取消；取消后迟到结果不能发布。

### 通信契约

| HTTP入口草案 | 行为 |
| --- | --- |
| `POST /api/v2/auth/login` | 独立身份，安全Cookie；管理员和学生权限分离 |
| `GET /api/v2/me/assignments` | 服务端选出当前可进入分配及待开始场次 |
| `POST /api/v2/assignments/:id/start` | 幂等初始化，返回完整快照与事件游标 |
| `POST /api/v2/modules/:id/enter` | 前模块完成后幂等进入；历史模块只回看，不改主游标 |
| `POST /api/v2/attempts/:id/uploads` | 创建受限上传凭证；完成后验证实际字节及归属 |
| `POST /api/v2/slots/:id/submissions` | 版本校验、提交题图并创建run，返回202 |
| `POST /api/v2/slots/:id/materials` | 新材料版本，仅重答该题 |
| `POST /api/v2/runs/:id/cancel` | 终态幂等取消 |
| `GET /api/v2/attempts/:id/snapshot` | 权限内当前事实及`lastSeq`，只读不调用模型 |
| `GET /api/v2/attempts/:id/events?after=` | 有界增量，过期游标要求重新取快照 |
| `/api/v2/admin/*` | 用户、模板/场次/分配、负责范围、看板、统计及审计 |

`/ws`同源Cookie握手，禁止URL密钥，消息使用共享schema。客户端订阅attempt及afterSeq，事件含schemaVersion、attemptId、seq、aggregateVersion、type和最小变更摘要；不传原图base64、内部thinking或全量管理数据。

每attempt用锁定流行分配序号，事件与状态同事务。不能把全局BIGSERIAL直接当无缝游标：并发事务可能后提交小号，导致跳过。管理端持有各attempt游标；分页快照与游标需同一一致性读。

[Redis Pub/Sub](https://redis.io/docs/latest/develop/pubsub/)可能丢消息，故仅用于唤醒API读取PG事件。先读快照，再按游标补齐；重复事件忽略，缺号补查。心跳15秒，45秒标连接异常，指数退避重连；连接不可用时5秒HTTP轮询，恢复后补齐并停轮询。后台唤醒必须重新同步。

## 放弃的方案

- 拍完就加序号：解题失败/重拍会破坏题位。
- 只靠WS或Redis推送保存结果：断线会失去可恢复事实。
- 全局强锁整场次等模型：补一题会阻塞其他学生。

## 后果与限制

上传对象与PG不是分布式事务：先隔离上传，校验后在提交事务关联；失败对象由补偿回收。实时看板目标正常网络下p95≤5秒，在线只是设备心跳，不等于学生正在阅读。网络抖动不能承诺绝对延迟。
