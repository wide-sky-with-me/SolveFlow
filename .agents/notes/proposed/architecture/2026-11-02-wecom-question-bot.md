# 企业微信群拍题机器人接入提案

日期：2026-11-02。状态：proposed。范围：企业微信题图接收、解题及回群；尚未实施。

## 背景

目标是群内发题图并自动解答。群类型尚未确认。已读取[官方指南](https://open.work.weixin.qq.com/help?doc_id=21657)、[消息接收](https://developer.work.weixin.qq.com/document/path/100719)和[长连接协议](https://developer.work.weixin.qq.com/document/path/101463)：

- 官方智能机器人长连接不支持外部群/客户群。群内需 @机器人；普通图片回调只支持单聊，群聊用图文混排或引用图片提问。
- 图片链接 5 分钟有效，每份资源有独立解密密钥；先保存图片，再排队解题。
- 同机器人只允许一个有效连接，新连接踢掉旧连接；网关单实例，计算可并发。
- 流式回复限首次发送后 10 分钟；同会话回复与推送合计限 30 条/分钟、1000 条/小时。HTTP 回调的 6 分钟轮询规则不能套到长连接。

SDK 核对至 `80615b9`。[引用结构](https://github.com/WecomTeam/aibot-node-sdk/blob/80615b987ef69c6028ad764924609247c0725955/src/types/message.ts)未承诺原消息 ID，不能按群中最后一题关联补图。

## 决定

以下为候选设计，须先确认内部群、创建及长连接权限。

1. 独立 `apps/wecom-bot` 用官方 SDK 收发，部署既有国内云，出站 WebSocket 不需新增公网回调端口。安装前锁定发布版，核对 MIT、依赖审计及体积。
2. 复用 [solveOnDevice](../../../../packages/agent/src/pi/mobile.ts)与[材料契约](../../../../packages/contracts/src/material.ts)，保留 ACT 转录、图片复核和校验/备用。公网分支的 Node 图片适配可供提取参考；旧 [API worker](../../../../apps/api/src/worker.ts)不能直接当作当前 ACT 入口。
3. 事件校验→下载规范化→持久任务→解题校验→回复记录。群/成员白名单及凭据独立配置；默认未指定考试，显式 ACT 等按题保存快照。
4. Bot、群、用户与 msgid 隔离任务并去重；独立 SQLite 与私有图片目录保存版本及投递状态，不混用浏览器历史。
5. 首版“发图→引用并 @”或“@＋图文同发”，返回短题号、选项、短解析及校验状态；处理中消息更新为答案，限制刷新频次。
6. 补图明确短题号，如“补图 Q7K2＋图片”，新版本只重答目标题。多图明确同题/分题，不猜相邻消息归属；后续支持卡片绑定和材料复用。
7. 首轮建议全局 4 题、每人 1 题，下载与每群发送另限流。重连不重复调用模型；重启后中断题等待显式重答，完成题只恢复投递。取消/补图后拒绝旧结果覆盖；回执丢失单列投递不确定，不承诺端到端恰好一次。

实施拆为通道、入站校验/下载、任务存储、核心适配、结果格式化及投递六个模块。先做单题闭环与权限/恢复，再加补图、重答和卡片；复杂公式图片与网页历史同步分别验收。测试使用独立机器人 ID，避免挤掉正式连接。

## 放弃的方案

- 仅群通知 Webhook：缺少题图接收链路。
- 整套 OpenClaw：本项目已有 Pi 编排，只需接消息通道。
- 客户群外挂/桌面挂机：没有本轮确认的官方稳定收发依据。

## 后果与限制

需新增任务存储与权限映射，用户 ID 按不透明标识处理。下载限制来源、重定向、字节/像素及超时，不能直接沿用 SDK 无大小上限的下载。日志禁存正文、签名链接及密钥。手机图文输入、复杂公式和原生引用效果仍需实测。ACT 转录、解题、校验及备用可能各发请求，额度按真实调用次数计，不能将一题等同一次调用。

若目标是客户群/普通微信群，可先提供现有网页入口；这不满足直接回原群，须另评估渠道。

## 验证

本轮仅官方文档、SDK与仓库静态核对，公开来源在忽略目录 `.runtime/wecom-research-2026-11-02/`；无机器人收发、模型请求或部署。

先用内部测试群验证引用题图/图文、解密及回群，再接核心与队列。覆盖重复消息、多人串题、过期/超大图、断线/回执丢失、重启、取消、补图竞态、限流和越权。真实题图外发另按端点与预算授权，未核验不标通过。
