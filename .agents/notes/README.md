# 决策笔记

这里保存“为什么这样做”，当前行为归 [子系统文档](../../docs/README.md)，开发要求归各层 `AGENTS.md`，测试证据归 `docs/postmortem/`。仅对架构、权限、持久化兼容、并发、生命周期或有证据的性能取舍写笔记；日常样式和机械改动不必写。

## 查找与生命周期

用 `rg --hidden -n '关键词' .agents/notes` 或跟随源码 `Decision:` 注释，不维护全局手写索引。路径为 `<状态>/<主题>/YYYY-MM-DD-英文名称.md`，状态取 `proposed`、`implemented`、`archived`；日期为实际记录日期，回溯整理须写明原始证据时间。

提案不等于授权或已实施。实施后移到 `implemented/` 并补实际验证；完整被替代时把原文移到 `archived/`，在策略文件登记其 SHA-256，新笔记链接旧文并迁移源码锚点。归档原文不改。局部替代不归档整篇，两篇写清适用范围。冻结登记随评审进行，不通过自动更新哈希接受变化。

## 模板

首行为标题，第二行留空，第三行使用下方日期/状态格式；两者必须与路径一致。检查器不从正文或代码示例猜测状态。

```markdown
# 决策标题

日期：YYYY-MM-DD。状态：implemented。范围：具体模块。

## 背景

具体触发条件、约束与原始证据链接；回溯笔记说明依据。

## 决定

实际选择与源码链接。不要复制整个 API/配置清单。

## 放弃的方案

实际讨论或实测过的方案及原因；没有记录的原因写“未记录”。

## 后果与限制

代价、兼容范围、后续风险和不适用场景。

## 验证

实际命令/结果或可核验报告链接，明确尚未执行的项目。
```

新笔记中的源码链接相对于笔记文件；源码注释使用仓库相对路径，例如 `// Decision: .agents/notes/implemented/storage/YYYY-MM-DD-name.md`。它是阅读入口，不生成运行时行为。检查范围和长度规则见 [变更流程](../../docs/cookbook/change-management.md)。
