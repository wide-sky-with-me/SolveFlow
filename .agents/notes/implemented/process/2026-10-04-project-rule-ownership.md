# 根规则归属与文档检查覆盖补充

日期：2026-10-04。状态：implemented。范围：开发规则与文档检查，不改变产品运行行为。

## 背景

用户级通用规则建立后，用户要求按相同实践修正项目。[根规则](../../../../AGENTS.md) 仍混有模块细则；`pnpm-workspace.yaml` 已引用依赖决策，却不在检查器的源码扫描范围。笔记正文日期没有核对，状态子串还会误接受与路径冲突的提案。

## 决定

根规则保留跨模块要求和阅读入口；Pi 接入细节、原生/DOM 约束、服务 owner 与测试资源责任由各自目录规则维护。仓库继续自足，不依赖开发者安装用户级文件。

[检查器](../../../../scripts/check-project-docs.mjs) 扫描既有目录中的 YAML，并用 [策略](../../../../scripts/docs-policy.json) 的可选 `sourceFiles` 显式列出根配置；沿用 schemaVersion 1，无此字段时保持原扫描入口。路径集合去重，不读取目录外目标或执行配置。笔记第三行按现有模板解析日期和状态，与路径精确核对；代码示例或其他正文不能充当头部。

这是 [原管理决策](2026-10-03-documentation-management.md) 的范围补充，其分层、长度预算和冻结政策继续有效，不归档仍然适用的原文。

## 放弃的方案

不直接复制用户级全文到仓库，也不删除所有通用底线使仓库依赖个人机器。没有递归扫描整个仓库根目录，避免把秘密、生成产物或无关文件加入管理检查；没有引入 YAML 执行器或新依赖，检查只识别显式注释。

不把全文某处出现的正确状态当作笔记状态，也不自动改正文日期去配合文件名；歧义必须由维护者处理。

## 后果与限制

仓库根新增带决策注释的配置要显式登记；仅支持既定注释和 Markdown 语法，不是完整语法树解析。元数据一致不代表决策已实施或事实正确，实际行为仍由源码和测试证明。冻结清单与 108 份历史内容保持。
