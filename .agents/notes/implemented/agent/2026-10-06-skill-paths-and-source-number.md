# 手机 Skill 引用与生成题号兼容

日期：2026-10-06。状态：implemented。范围：受审手机资源生成、共享生成结果边界、设备及保留服务适配。

## 背景

[生物复核](../../../../docs/postmortem/2026-10-06-biology-batch-review.md)记录了 `problem.sourceNumber` 格式失败导致额外模型请求，但未保存原始值，不能认定当时具体是哪一种类型。检查还发现学生 Skill 的参考使用服务路径 `/solveflow/skills/`，设备 `read` 仅允许 `/skills/`，会使按正文加载参考失败。严格存储契约和路径白名单必须保留。

## 决定

- [资源生成器](../../../../scripts/prepare-mobile-agent.mjs)仅在明确受审的 Skill 内容中把固定服务前缀转成设备前缀。服务器继续使用源资源与原路径；不接受额外目录或任意别名，不扩大白名单。
- [共享兼容函数](../../../../packages/contracts/src/model-output.ts)只在新 Solver 输出边界，将可选 `problem.sourceNumber` 的非负安全整数转换为字符串，null/空白字符串视作未提供；最多处理四题的同名元数据。已有字符串原样进入严格 schema，含小问等题号不重编号。
- [设备适配](../../../../packages/agent/src/pi/mobile.ts)和[服务适配](../../../../packages/agent/src/pi/phase-runner.ts)在原有严格候选校验前使用同一兼容函数。答案、选项、题内身份、证据、未知字段和校验结果不做兼容；其他错误沿用既有有界修复或失败。
- 学生提示明确题号字符串及缺省方式；各 Skill 的作答形态服从系统题型规则。无标签选项仅在全部文字与顺序可读时使用说明过的应用索引，可见原始标签仍不可重编号。

## 放弃的方案

全局将存储 schema 改成字符串/数字/null 联合会改变持久化语义，并使显示与历史调用方承担额外分支。对所有字段做宽松转换或删除异常字段会掩盖答案错误。允许服务路径作为设备任意别名会增加路径规则和授权边界；生成时转换受审内容更局部。对每次题号格式问题重新调用模型保留不必要的时间与费用。

## 后果与限制

没有存储版本、迁移、模型/工具权限或总预算变更。兼容只处理不影响答案含义的题号表示，不能证明题号来自原图；实际原题号仍由转录及独立核验确认。旧记录继续按原 schema 读取。

规则变化与一次格式修复减少不能证明正确率提升，也不解释原始超时原因；真实模型复测单独 opt-in。资源生成后须重新构建客户端才进入应用。

## 验证

[共享契约回归](../../../../packages/contracts/src/agent.test.ts)覆盖不可变性、多题、模糊类型和严格拒绝；[设备回归](../../../../packages/agent/src/pi/mobile.test.ts)核对模型调用次数与答案错误仍须修复；[Responses/路径回归](../../../../packages/agent/src/pi/mobile-exams.test.ts)及[服务回归](../../../../packages/agent/src/pi/phase-runner.test.ts)验证消费方一致性。实际命令、失败及复测见[修复验收](../../../../docs/postmortem/2026-10-06-biology-reliability-fixes.md)。
