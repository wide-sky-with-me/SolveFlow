# 答案检查点与独立校验队列

日期：2026-10-08。状态：implemented。范围：设备业务队列、答案持久化、后台保护、补图与手动计时。

## 背景

用户测试发现答案很快生成，但校验占用批量槽位，后续题目和答案展示一起等待。补图只保存材料，旧答案的校验继续使用旧证据范围，界面未明确提供全材料再解答。今天的只读诊断及复测见[验收](../../../../docs/postmortem/2026-10-08-exam-flow-review.md)。

## 决定

校验容量反压与固定并发部分已由[独立批量并发](2026-10-09-independent-batch-concurrency.md)替代；下文保留当时选择，答案检查点、取消、材料与恢复语义继续适用。

[引擎](../../../../packages/client/src/local-engine.ts)在模型候选结构有效后，锁内重新读取会话、保存 completed/pending 候选，再发布外层 verifying 状态；这只是答案检查点，不能成为 verified。每题最终写入仍只合并自己的 run，取消优先。

[批量队列](../../../../packages/client/src/local-batch.ts)释放已落盘且进入校验池的 solver 槽位，允许三路求解继续；校验单独 FIFO 一路并发，八个已接收校验输入上限，满额时三路求解在展示候选后等待容量。最多保留十一份输入，避免整批图片常驻内存。[资源准入](../../../../packages/client/src/phase-queue.ts)只控制容量与取消，不执行或重放模型，Pi 仍拥有工具循环。记录排队诊断或恢复保护失败也释放已取得的校验位；排队耗时采用单调时钟、保存整数毫秒。等待校验期间暂停单 run 原生保护，取得执行位后恢复；最多三求解加一校验占用实际后台任务。

[共享编排](../../../../packages/agent/src/orchestration/solve.ts)持有一次校验槽位直到检查、一次纠错和复核结束，修正候选同样经过持久化检查点；[设备适配](../../../../packages/agent/src/pi/mobile.ts)转发生命周期接口。批量停止取消等待者及活动请求；新进程不恢复队列、不重放付费请求。

[仓库](../../../../packages/client/src/local-repository.ts)恢复已落盘候选为 completed/未验证并附 WORKER_LOST；没有候选仍恢复失败。检查点写入失败不启动校验，最终保存失败沿用待保存保护。[请求准备](../../../../packages/client/src/local-run-request.ts)保留旧版本快照，不能让新图偷偷改旧答案的证据。

[运行时](../../../../apps/mobile/src/runtime.ts)和[补图入口](../../../../apps/mobile/src/components/question-materials.tsx)新增显式全材料再解答，创建新版本并保留旧答案；同图多题明确选择目标，其他批量题活动不妨碍空闲题补图。仅保存补图不自动付费。

[四态投影](../../../../packages/contracts/src/question-state.ts)以当前答案版本及其独立检查确定绿/橘/红/灰，失败的辅助检查不抹掉已有答案。[手动秒表](../../../../apps/mobile/src/components/study-stopwatch.tsx)不依赖模型状态，按会话与图内题号保存开始时刻和累计用时；开始、停止、续计和重置均由用户操作。保存后随本题删除，未纳入题目备份。

## 放弃的方案

继续以整次解题加校验占用同一槽位不能解决首答延迟。只在内存发布答案会在刷新或进程退出时丢失已生成结果。一次加载整个校验批次会扩大图片内存；因此采用有界背压。把补图并入旧校验快照会改变旧版本含义；采用明确的新答案版本。

## 后果与限制

繁忙时会存在可读但尚未校验的答案，必须显示橘色和等待提示；不能由内层 completed 判定任务终态。累计等待不计入模型阶段窗口，但排队仍可取消且有容量上限。严格旧客户端可能拒绝 pending、选项完整性和新诊断字段，不允许降级覆盖。系统杀进程不自动恢复人工计时按钮动作以外的模型工作。

本决定局部替代[旧本地准备](2026-10-03-local-request-preparation.md)中批量槽位直到最终写入才释放的语义；准备锁、取消补写与删除顺序继续有效。[待保存结果](../storage/2026-10-03-pending-result-save.md)的拒绝新任务与仅保存重试保持，最大已接受输入随本次队列容量变化。

## 验证

离线 Vitest 118 文件、1066 项通过，包含六题先答再验、停止等待者、十一输入背压、中断候选恢复及平台诊断异常后继续派发。浏览器与真实题图结果另见上述验收；Android 真机与 Mac 原生构建不由离线测试代替。

2026-10-09：逐题计时的归属和界面由[整体手动计时](2026-10-09-overall-study-timer.md)局部替代；答案检查点与队列不变。
