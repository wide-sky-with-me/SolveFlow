# PDF 执行发布与终态补存

日期：2026-10-17。状态：implemented。范围：本地导出队列 runner 派发及取消/超时补存幂等，不改变任务协议、存储版本或执行期限。

## 背景

[准入取消决定](2026-10-17-pdf-admission-cancellation.md)只闭合 enqueue 的首次写入及 queued 发布，不将调用者 signal 绑定为已接受任务生命周期。已接受任务的 run 把 running 保存并发布后，经一次 await 返回到派发处。订阅者在发布中同步取消或排入微任务取消，虽能最终保存 cancelled，但旧流程仍创建期限计时器并调用持有已 aborted signal 的 runner。Web 准备回调因此仍会被进入；最终无成品不等于未启动准备。

独立复核还发现既有补存身份漂移：取消或超时终态写入实际成功、但回执随后报错时，catch 再应用停止意图会用推进的时钟重建 finishedAt。磁盘原对象与内存新对象因完成时间不同，在严格终态冲突检查中相互冲突。原固定时钟回归掩盖了此路径，推进时钟与原生事务完成后丢回执的回归另行复现。

## 决定

[队列实现](../../../../packages/client/src/local-export-tasks.ts)在 running 写入/发布的 lock 兑现后、创建执行计时器及调用 runner 之前，复核执行控制器。已取消则仍在原 active 所有权内，通过 I/O 串行锁等待取消收尾，随后由原 finally 清理 execution 并推进其它排队项。不调用 runner，也不创建本次执行期限；不改已经开始的 runner 的协作取消规则。

直接检查执行控制器而非准入 signal，保留接受后的任务 ID 取消语义。取消保存故障沿现有有界 pending 状态和存储重试，不让此处恢复生成或自动再试持久化。未取消的派发、已存在的写入前后检查及截止预算均不变。

重应用取消/超时意图只在目标状态尚未匹配时构造终态；已是 cancelled，或已是带原超时原因的 failed，则保留包括 finishedAt 在内的完整身份。取消优先级和严格 JSON 全等/已记录成功修正门禁不变，不放宽“已有其他终态”的保护。重试补存沿用首次目标终态，不因回执失败或重试改记完成时间。

此决定补充[后台导出所有权](2026-10-14-background-pdf-exports.md)与准入决定，不替代其后台存续、捕获容量、保存/通知与刷新恢复规则。[当前语义](../../../../docs/subsystems/batch-pdf.md)和[当次证据](../../../../docs/postmortem/2026-10-17-pdf-dispatch-cancellation.md)分别维护行为与成绩。

## 放弃的方案

只要求每个 runner 自己在开头检查会继续调用准备代码，第三方调用方也可能忽略信号，故队列负责派发门禁。不只在 emit 后同步检查：微任务取消发生在 lock 兑现后的执行继续之前；检查应位于实际派发边界。不因控制器已取消便直接 return：取消存储可能仍挂在串行锁上，保留 active 到收尾更明确，也保持 waitForIdle 的等待范围。

不重构全部时序、延迟 running 的持久化或将其改回 queued，不新增调度器、全局 signal 监听、重试计时器或存储迁移。仅为本窗口创建额外派发任务会增加调度面，未采用。

不通过忽略 finishedAt、只比较 status 或允许覆盖任意 cancelled 解决冲突：这些会放过真正不同的持久终态。也不凭回执报错猜测原生事务未提交；保存重试仍先读持久状态再判断所有权。

## 后果与限制

这是取消正确性与避免无用准备的修复，不宣称光栅化加速。running 历史可以短暂可见；即刻取消仍需等待底层存储兑现。已经进入 runner 的工作继续依赖 signal、原截止期限及迟到结果门禁，不承诺强制抢占任意同步第三方函数。

没有改变超时后的生成槽所有权或持久化故障对其它等待任务的既有行为。真实跨浏览器、低内存设备和绘制长任务仍单独验收。

## 验证

[核心回归](../../../../packages/client/src/local-export-tasks.test.ts)覆盖同步/微任务发布取消、不创建期限计时器、排队晋升、后继任务与 waitForIdle 在取消写入期间仍等待、故障中断后继；推进时钟覆盖取消/超时保存前后故障及补存身份不漂移。[Web 适配集成](../../../../apps/mobile/src/local/web-export-admission.test.ts)组合真实队列与实际适配源码、合成存储/渲染，验证准备/绘制不进入、无成品、取消后满容量再提交成功。[浏览器回归](../../../../tests/mobile-e2e/background-exports.spec.ts)在隔离页面的 running 快照发布边界触发实际按钮，结合执行信号观察、UI反馈和零成品；另在取消原生事务完成后模拟回执故障，验证原位保存重试及磁盘终态不变。具体失败和复测以当次证据为准。
