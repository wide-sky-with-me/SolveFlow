# 打印测量与截图保持标准模式

日期：2026-10-22。状态：implemented。范围：Web试卷打印帧。

## 背景

快速导出那轮修复只覆盖长图选项，并未覆盖用户实际40题批次。仅复制指定站点IndexedDB到私有浏览器、拦截全部网络后复现相同错误。第一题原帧BackCompat且无doctype，截图克隆CSS1Compat；表格行高从约26px变为31.5px，题干616px增至673px。原帧勉强可缩排，截图重测低于8pt底线才抛错。证据见[本轮验收](../../../../docs/postmortem/2026-10-22-print-document-mode.md)。

## 决定

[打印帧](../../../../apps/mobile/src/local/print-batch.web.ts)在接入样式和正文前以固定doctype声明同步初始化标准文档，再沿原DOM克隆、资源等待及续页路径测量。声明是唯一静态解析内容，不拼接用户题文、图片或模型HTML。源与克隆先按同一模式计算尺寸，真正的长题由原续页器处理，页数和8pt底线不变。

原[续页决定](2026-10-21-question-continuation-pages.md)与[快速导出](2026-10-22-direct-parsed-pdf.md)继续有效，本决定只统一模式，不以更小字号、删内容或关闭溢出检查掩盖失败。

## 放弃的方案

DOM插入doctype节点经空白浏览器验证不会改变现有BackCompat，不能修复测量。截图失败后强制再分一次页仍建立在不同表格行高上；未采用该启发式。改为异步srcdoc会引入额外导航、取消和资源就绪边界，固定声明同步初始化即可避免这些变化。

## 后果与限制

标准表格行高可能增加实页数，保留正文、表格和图示；缓存与原题不变。不能用本轮排版通过证明答案正确。用户原Windows浏览器不修改，临时副本和原题产物清理后仅保留脱敏几何、哈希及结果。
