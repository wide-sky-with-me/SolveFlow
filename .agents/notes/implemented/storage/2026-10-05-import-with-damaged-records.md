# 损坏记录旁的普通备份合并

日期：2026-10-05。状态：implemented。范围：设备仓库的备份导入与损坏隔离。

## 背景

[导入回归](../../../../packages/client/src/local-history-import.test.ts) 复现已有一条损坏元数据时，其他题目的完整备份也无法合并。原实现要求所有现存题目都能读取，破坏了健康记录独立可用的边界。本次局部补充[原备份决策](2026-10-03-backup-and-atomic-repair.md)，原事务、分卷和明确确认替换原则继续有效。

## 决定

[仓库](../../../../packages/client/src/local-repository.ts) 保留坏记录及无效记录键的字节和容量占用，仅跳过其无法读取的元数据。有效元数据不依赖可选批次名称，仍用于归属检查；独立诊断键预留 run ID，坏题的有效摘要保守预留批次位置。已有文档键不能被导入覆盖。I/O 故障继续抛出，不能当作损坏隔离。

## 放弃的方案

继续要求全库健康会让一个坏题阻断其他题目恢复；直接删除坏题违反原数据保留要求。单纯忽略读取异常会隐藏 I/O 故障和现有诊断键冲突，因此只隔离 LocalDataError 并预留可识别编号。不从无效 JSON 中猜测归属。

## 后果与限制

不更改磁盘或备份版本。坏题没有有效摘要或诊断键时，隐藏的引用无法提前识别；后续单题修复仍检查可读取题目的编号冲突，不能覆盖健康题目。有效但过时的摘要可能保守拒绝同批次位置，需要先修复坏题。原数据与诊断不会因隔离被删除。

## 验证

修复前新增回归有三项失败，涉及普通合并、独立诊断及批次冲突；I/O 拒绝场景通过。修复后的命令和结果见[验收记录](../../../../docs/postmortem/2026-10-05-recovery-repair.md)，真机范围单独说明。
