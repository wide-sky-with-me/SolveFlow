# PDF 准入在独立阶段之间让出主线程

日期：2026-10-16。状态：implemented。范围：Web 前台/后台导出准入，不改契约或存储格式。

## 背景

[当前构建采样](../../../../docs/postmortem/2026-10-16-pdf-admission-yield.md)中，初始化已兑现时，预检、字节计数/整份克隆和接受快照复核连续执行，形成约一秒长任务。原前台取消只在拿到任务 ID 后接到任务队列；准入等待期间的取消仍可能走到入队。

## 决定

[任务适配](../../../../apps/mobile/src/local/web-export-tasks.ts)在预检前、初始化后、克隆后及入队前使用独立 MessageChannel 消息任务让出，并复核调用者取消。初始化共享等待可独立取消，继续消费迟到成功/失败，不终止其它调用者的初始化。每次让出只持有一对端口，成功、失败或取消均清空回调、关闭端口和释放监听；宿主错误用静态文案，清理异常仍以原取消为先。实现由[准入适配](../../../../apps/mobile/src/local/export-admission.web.ts)拥有，消息标识不带业务数据。

[前台入口](../../../../apps/mobile/src/components/batch-pdf-export.web.tsx)将已有操作 signal 传给准入；入队后仍沿原任务 ID 取消及下载复核。后台入口不新增操作 UI，接受后仍由任务队列持有生命周期。

字节计数、容量门槛和 structuredClone 保持在同一同步段，计数后到克隆间不 await，避免调用者修改形成低估。冻结仍发生在初始化后、容量校验后；新增让出可能延后捕获，故接受快照完整复核，不沿用让出前题数，并再次检查 300 页门槛。捕获后不再读取调用者输入。提交锁贯穿所有让出；失败释放预留字节/订阅，未入队取消不创建任务或模型请求。

## 放弃的方案

[原快照投影决定](2026-10-16-export-snapshot-projection.md)仍有效：公开 unknown 入口完整验证，不跨异步阶段仅凭对象身份跳过校验。本次没有减少验证次数或将计数/克隆拆开。

任务私有已验投影可减少重复扫描，但需新增内部所有权接口，仍有单次校验/克隆下界，未采用。逐记录异步验证需要拆分共享 schema、完整隔离视图和错误等价测试，留待实测后续优化。Promise.resolve/parseAsync 不保证让出浏览器任务；未用 rAF 等待，以免把准入绑定到可见帧。MessagePort 采用标准接口，见 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/MessagePort/postMessage)。

## 后果与限制

不是工作线程或全链路可抢占；单次全量验证及计数/克隆仍同步，消息任务也不承诺每次都绘制一帧、特定优先级或耗时下降。取消只作用于尚未完成的准入，接受后沿原任务取消规则。存储写入交接边界后由[入队取消决策](2026-10-17-pdf-admission-cancellation.md)局部替代；其余决定继续有效。

## 验证

[准入回归](../../../../apps/mobile/src/local/web-export-admission.test.ts)覆盖阶段、取消、并发锁、容量释放、调用者突变与页数优先；[资源回归](../../../../apps/mobile/src/local/export-admission.test.ts)覆盖真实任务让出、端口/监听释放、宿主错误、取消优先及迟到初始化失败。[浏览器回归](../../../../tests/mobile-e2e/background-exports.spec.ts)通过独立消息标识定位各阶段，实际点击取消并核对无入队、无模型、无根/frame、无成品。命令与实际成绩由当次验收报告拥有。

## 2026-10-17 捕获策略复核

保持原生整图克隆，不以 schema 解析、浅复制或 JSON 往返替换。解析会修剪文字或补默认值，也不覆盖整个 copies/prepared；提前采用解析结果会改变原始任务标题、reading 准入与错误阶段。prepared 中的布局容器仍可变，既有捕获负责隔离无 prepare 回调路径；后生成的 prepare 返回值仍由原调用方生命周期约束，不宣称也由准入克隆独占。

实测后暂缓消息通道大数据捕获。[标准](https://html.spec.whatwg.org/multipage/web-messaging.html#message-port-post-message-steps)在发送调用中同步序列化、接收任务中反序列化；拆分接收不等于工作线程。探针显示发送仍是长任务，总耗时无稳定收益，且待收消息的取消/收尾尚未验证。任何后续候选仍须保留同段计数与捕获、深层隔离、别名和原生值语义，并证明等待消息期间的所有权及迟到收尾。

新增回归锁定捕获前深层修改纳入、捕获后双向隔离、稀疏数组/共享引用/非 JSON 原生值、原始标题、克隆及计数失败后的重试。定向替身仍模拟页数和字节函数，不将其当作全契约或真实绘制验收；本轮未改变产品路径。实际分阶段证据、探针纠错及验证范围见[当次报告](../../../../docs/postmortem/2026-10-17-pdf-native-capture.md)。

## 2026-10-19 捕获复核局部替代

[私有捕获逐记录复核](2026-10-19-pdf-captured-validation.md)局部替代捕获后整份同步校验：只在提交方独占的原生克隆上逐记录让出，仍完整验证并保留失败issues；初始化前预检、容量计量/原生捕获同段及其余所有权/交接约束继续有效。
