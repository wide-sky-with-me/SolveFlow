# 部署侧一次性标准恢复

日期：2026-10-14。状态：implemented。范围：已部署 Web 的指定客户端试用批次恢复，不改变题库归属或模型配置。

## 背景

用户明确要求后台恢复，不再手选备份。运行中的用户 Chrome 未开放调试入口；题目在客户端 IndexedDB，不在 Docker。写服务端状态或隔离测试浏览器不能恢复其当前浏览器。

## 决定

沿用[固定入口](../architecture/2026-10-14-container-web-loopback.md)门禁，增加校验后的可选部署路由；默认不启用。操作副本在宿主私有目录，只有已实测出口192.168.100.120且本次恢复时窗内收到启动前恢复页。刷新卸载旧应用，恢复页取得相同 Web Lock，复用标准 LocalRepository.importHistory，校验固定长度和SHA256，完成后写本地回执、释放锁并跳至原批次。再次执行跳过已有题目，不覆盖收藏及设置。

## 放弃的方案

不直接改运行中 Chrome 的数据库文件，也不绕过应用锁。没有改全部设备的默认题库或把学习内容放进镜像。启动前恢复页用于隔离应用与恢复写入；其他标签持锁时提示先关闭。原始备份只读保留，取消和格式失败沿用标准恢复器的检查/撤回。

## 后果与限制

当前操作期限为2026-10-14 13:45 +08:00，其他IP不获取恢复页及私有文件，之后网关自动回到原服务。IP变化要重新核对。本地回执随该浏览器存储保存，不代表其他设备已恢复。退出部署任务或恢复旧launchd配置可撤回，既有记录不删除。原题库和同批数据源不修改。
