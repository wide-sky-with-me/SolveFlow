## 范围和产品边界

用户要求两名子 Agent 分别审阅前端操作与本地解题核心/保留后端，并交换发现交叉核验。frontend_review 主审相机、单题/批次、按需操作、页面状态；backend_review 主审持久化、契约、校验执行和旧服务路径。两者已互审历史导入、定向校验、前端并发取消修复；主 Agent 汇总、复核并处理显示与打包边界。

Pearson 是用户在电脑上打开的外部官方样卷展示网站。手机在 SolveFlow 内拍摄题目，再走现有裁切、考试快照、解题和核验路径；应用不提供 Pearson 页面、账号、播放器、嵌入浏览器或试卷接口。受审考试方法参考保留来源网址，不因此发起网页请求。拍照时题干、图表与全部选项须完整，答案解析不进入照片。

已有 0.1.64 APK 扫描 634 个条目及 14 个 assets，未发现 Pearson/StartTestLaunch/testtaker 播放器标记或评测目录。`scripts/check-apk.mjs` 新增打包检查，拒绝播放器地址和本地评测试卷/答卷目录。安装包仍只包含应用、解题核心和受审参考。

## 确认的问题与修复

| 发现 | 原因与修复 | 回归依据 |
| --- | --- | --- |
| 按需按钮可点却不发起 | `question-thread.tsx` 的步骤与步骤校验处理使用普通对话的 activeId 禁用条件；改用与 UI 一致的 auxiliaryDisabled，允许步骤、知识点和校验三类并发 | 旧 Web 产物已复现；按不同启动顺序测试 |
| 取消一个按需任务却取消全部或其他任务 | 通用取消回调没有任务标识；从题目/步骤/知识点按钮传递实际 runId，经 `engine.cancelRun` 定向取消 | 三类请求并发时取消其中一种，另两种继续；覆盖单题与批次 |
| 配置模型后批次按钮仍禁用 | memo 化的 BatchQuestion 读取可变 settings getter，缺少触发重新渲染的参数；将 Workspace 的 available 显式传入，加入 renderPage 依赖 | 先打开已有批次、再配置模型，回到批次发起按需操作 |
| 恢复未收藏历史后列表和再次导出报错 | 导入写入 favorite=false，但存储 schema 只接受 true；未收藏改为缺省/删除键，收藏使用同一 schema | 旧代码回归出现 expected true；导入→列表→读取→再次导出验证 |
| 旧 API 校验已有答案却重新解题 | worker 没有设置 verificationTarget；改为从当前 owner 会话的已保存源记录按题号投影，传入候选，仅运行 Verifier | 隔离 DB/桶下，单题及多题检验角色只有 verifier；FAIL 保留原答案且不重新求解 |
| 旧服务完整教学信息守卫失效 | 本地按需 schema 的知识点变为可选，旧服务仍借此判断完整性；恢复仅适用于旧完整教学路径的检查，不收紧设备按需行为 | 既有 missing-learning 集成用例先失败后修复，保留断言 |
| 美元符号和中文下标显示失败 | 公式内转义美元被 Markdown 当作结束符；改为等价字符命令。明确的连续金额散文转义为普通货币文本；中文字符仅放开 KaTeX 兼容性告警 | 单元先复现，实际 Markdown/KaTeX 页面测试；信任关闭、宏展开/尺寸上限及无效语法回退保持 |

没有修改 Pi 循环、工具能力、模型路由或 120 秒总预算。设备 Verifier 已有的 30/40 秒上限与旧服务 20 秒不同，本轮只纠正文档表述，没有再次扩大运行时预算。
