# AGENTS.md — 文档维护

- `architecture.md` 只画当前系统地图；`subsystems/` 描述运行语义和失败边界；`cookbook/` 给操作步骤；`postmortem/` 保存事故、验收与实际证据。
- 开发约束放相应目录 `AGENTS.md`；长期决策原因、放弃方案与后果放 `.agents/notes/`。不要把每次任务流水账追加进架构文档。
- 同一事实一个维护位置，其余地方链接。协议/命令/配置的完整清单以源码为准，不手抄 API 目录。文档链接必须指向真实文件。
- 文件命名、标题层级、日期、单位和引用按 [编写约定](cookbook/documentation.md)；报告按 [复盘模板](postmortem/README.md#报告模板) 交代范围与结论，不依赖聊天序号。
- 当前说明使用当下语义；历史演变、旧成绩、原始测试时间线属于归档或复盘。短期进度不写成永久能力声明。
- 中英文均受 [长度策略](../scripts/docs-policy.json) 限制；超限先拆分或精简，确需提高上限须在决策中说明，不能自动放宽门槛。
- 旧报告/ADR 为原路径冻结档案，清单与哈希由策略文件记录；不新增同类散落文件，不改旧结论。纠错或替代新增有来源的笔记并链接前文。
- 非平凡变更才创建笔记；小样式、重命名和机械修改无需一篇新文档。禁止全局手写 notes 索引，按目录、代码锚点和搜索发现。
- 文档不放密钥、原题图、完整模型正文或可用签名 URL；真实图片、日志与 APK 放忽略目录。
- 完成后运行 `pnpm docs:check`；检查器变更加 `pnpm docs:test`。不要为纯文档修改启动应用或声称应用回归通过。
