# 大图及后台恢复的边界复查

## 范围与结论

2026-11-03，`feat/public-photo-web`工作区增量。沿[上一轮修复](2026-11-03-iphone-input-background.md)继续检查图片预处理、公网任务取消和恢复；不改主分支或远程部署。使用合成图片和假模型，真实付费请求0次。

## 复现与修复

| 问题 | 原本行为 | 修正 |
| --- | --- | --- |
| 上传/准入期间停止无效 | 取消只查active任务；图片稍后上传完成，或额度写入结束后，仍派发模型 | 按受信身份与请求ID同步登记有界取消标记，准入和落盘后再次检查。补传到达也不会派发；状态读取等待准入完成，避免把中间状态误判为重启遗留 |
| 取消404后页面卡住 | 未接收上传没有远程记录，取消404被当成错误，本地恢复标记不清除，“拍下一题”持续禁用，刷新后仍卡住 | 取消404按无远程活动任务处理，结束相同本地运行、移除待同步标记；取消不覆盖已完成或更新的答案 |
| 宽幅图文字变糊 | 解码宽度误取原图短边，先缩小后又放大到预览尺寸 | 有界读取JPEG/PNG/WebP的EXIF方向，按实际方向和目标比例设置解码尺寸，不降低原尺寸/字节限制 |
| 取消时图片资源泄漏 | Worker已转移ImageBitmap、主线程尚未编码时收到取消，抛错绕过close | 取消检查移入资源释放保护范围，取消及画布创建失败也关闭位图 |
| 混用新旧入口超身份并发 | 新任务接口与旧流接口分开统计同身份执行数，可超过原有上限 | 两入口共用身份及全局计数，满额返回429，不再派发额外请求 |

取消标记、状态/准入顺序及有界查询队列的长期原因见[决定](../../.agents/notes/implemented/architecture/2026-11-03-photo-cancellation-admission.md)。当前行为归[公网指南](../cookbook/public-photo-web.md#任务与连接恢复)及[图片输入](../subsystems/image-input.md)。

## 未验证项与剩余风险

本轮没有真实模型、真实iPhone相机/锁屏、低内存或iCloud原图测试。iOS原生后台模块未改，上一轮模拟器/编译成绩不计入本次。WebKit与移动视口不代替真机；大图通过不等于识别准确率提高。

断网时停止请求不能保证立即送达服务器；恢复网络后继续取消，不自动重传图片或重答。服务崩溃、磁盘故障及24小时可恢复窗口沿原文档。主分支、公网和远程Mac线上服务未更新，未提交或推送代码。
