# 批量采集、答题与多份导出的提速审查

日期：2026-10-25。范围：当前本地工作树的交互及调用链，Linux Chrome隔离渲染基准；未修改应用行为、运行付费模型或部署Mac。

结论：现有保存后即入队、独立答题/校验已经重叠执行。进一步机会集中在导出预设、提前配置并自动串联、避免多份重复栅格化；单纯提高模型并发不能消除导出CPU、文件大小及存储等待。下述优化均为建议，尚未实现。

## 当前链路与发现

1. [采集](../../apps/mobile/src/components/batch-capture.tsx)在当前图归一化、保存、入队后返回；[相机](../../apps/mobile/src/components/camera.tsx)等待此回调才解除忙状态，因此不等模型，但仍等图片处理/保存。相册已用[两张预处理缓冲](../../apps/mobile/src/batch-photo-preparation.ts)，没有先等50张全部处理完才答题，不应将已有能力当新增优化。
2. [队列](../../packages/client/src/local-batch.ts)答案落盘后释放答题名额，校验走独立容量；ACT目前[转录再解题](../../packages/agent/src/pi/mobile.ts)的同题依赖是完整性修复的一部分，不能靠直接删除转录或校验换速度。
3. [批次操作](../../apps/mobile/src/components/batch-workspace.tsx)用全局queueBusy/engine.actives禁用导出入口，不能在本批运行期间提前配置；其他批次仍在执行，也会阻止已完成批次打开。真正[快照收集](../../packages/client/src/batch-print.ts)另有本批成员/活动状态复核，后续可按本批准入并固定终态快照。
4. [导出窗](../../apps/mobile/src/components/batch-pdf-export.web.tsx)每次默认paper、1份、错0，未记住上次版式/份数/错题数量/备注方案。[副本设置](../../apps/mobile/src/components/batch-copy-settings.web.tsx)逐行输入，没有列表粘贴、循环填充或方案复用。
5. 即使最终选择direct，[初次读取](../../apps/mobile/src/components/use-batch-pdf-export.web.ts)仍先读全批记录并恢复paper整理缓存；[缓存键](../../apps/mobile/src/local/batch-print-cache.web.ts)对含图片的输入JSON编码并求哈希，缓存恢复又逐记录打开IndexedDB。快速入口可绕过这段，版式切换后再按需恢复。
6. [快速渲染器](../../apps/mobile/src/local/direct-batch-pdf.web.ts)跳过模型和html2canvas，但每份仍重算换行/分页、逐页画Canvas并转JPEG，再创建独立PDF。尺寸映射已跨份缓存，实际绘制仍逐次new Image。纯文字也被整页栅格化，未直接使用PDF文字对象。
7. [下载路径](../../apps/mobile/src/components/batch-pdf-export.web.tsx)等[导出队列](../../packages/client/src/local-export-tasks.ts)写入成品后，再[读回](../../apps/mobile/src/local/web-export-tasks.ts)完整文件并创建下载Blob。大ZIP存在生成后写库/读库的额外等待。后台导出仍在访问者浏览器执行，不是将渲染卸载到Mac服务。

## 实测

直接打包现有`buildDirectBatchPdfs`，预热一次后各测一次。每组50题，合成英文正文、四选项、答案总表与黄色高亮；带图组各题一张2000×1500合成JPEG。四组顺序运行，外部网络拦截，无模型/真实题图、无IndexedDB或下载落盘计时。私有脚本、原始JSON和日志位于`.runtime/batch-throughput-review-2026-10-25/`。

## 建议顺序与验收边界

| 优先级 | 改进 | 具体交互或实现 | 验收重点 |
| --- | --- | --- | --- |
| P1 | 导出预设与快速入口 | 记住版式、标记开关、错题数量序列；例如10份按1、2、3、4循环，支持粘贴备注名单。一键按上次方案快速导出，direct入口不先恢复paper缓存 | 新题数校验、取消不覆盖、参照答案不跨批误用、重复打开不清空 |
| P1 | PDF正文/图片复用 | 英文等直接写PDF文字，题图按导出清晰度要求处理一次后嵌入；测宽和不变内容按有界缓存复用，答案表/作答/标记逐份生成。保留书签、黄底及全部题干 | 同计划与原图逐题对照、中文/特殊字符与字体回退、每份正确分页和跳转、取消释放 |
| P1 | 预先配置，完成后自动导出 | 答题期间能先设份数/错题数并显式选择完成后出卷；本批结束后固定最新快照，生成ZIP并通知，无需回来等待再点 | 只等本批、补图/重答后版本一致、失败题明确处理、不自动重放付费任务 |
| P2 | 轻量答案输出 | 增加“只要答案表”或“公共题干1份＋多份答题页”，完整多份PDF继续保留 | 用户显式选择；各份错题计划、备注及答案映射一致，不默默省题 |
| P2 | 下载与存档分开 | 可选生成后先下载，独立继续存入导出记录，避免下载再等待大文件读回 | 下载成功与存档成功区分；保存失败可恢复，取消及内存仍有界，不返回伪保存成功 |
| P2 | 连拍处理缓冲 | 快门与两三张有界图片处理流水线重叠，满额才暂停；保存完成才显示已加入/派发 | 不能关窗丢图、顺序不变、EXIF/尺寸约束保留、存储失败后停止，不虚报保存 |

现有[jsPDF](https://github.com/parallax/jsPDF)支持文字及嵌入字体，[图像接口](https://parallax.github.io/jsPDF/docs/module-addImage.html)可嵌入本地JPEG，方向不需要新增模型请求；中文/缺字仍须设计字体与回退。不同答案可能改变行高，不能盲目复用第一份的整页位置；必须以本份计划生成答案及最终书签。图像缓存须按像素/字节淘汰，不能一次解码50张大图常驻。
