# PDF 完整转录表格的去原图修复

日期：2026-10-20。

范围：`feat/batch-pdf-unified` 工作区候选构建；Linux Chrome 154、Playwright 1.58、Node 24.21；一个既有生物题图语料的 27 条合成记录。未替换现有服务。

结论：完整转录的表格不再因旧图示标注强制附照片；真实参考版下载及重开复用通过。不是严格模式、全自动整理或全卷视觉认证。

## 变更与处理

用户再次明确“非必要不需要原图”。旧遗漏保护把数值表的历史图示标注视作必须保图，完整转录仍恢复原题及整图。先前强制表格裁片的提示词方向已撤回，改用[显式处置决策](../../.agents/notes/implemented/agent/2026-10-20-print-illustration-dispositions.md)：逐项覆盖旧 ID、实际排入题干的转录或真实图源/裁片引用；未覆盖图示、选项、归属与疑点保护不变。

首次真实复测又暴露合法空白表头被判无效：原表左上角留空，转录按原样保留，但新增检查错误要求每个表头都有文字。补失败回归后允许真实空白表头，仍验证完整列数、分隔行、数据行及非空内容，不补造列名、不靠保留照片放行。

## 验证结果

证据根为 Git 忽略的 `.runtime/pdf-production-2026-10-16/`；候选绑定 `r98-transcription-v2-candidate-binding.json`，实际浏览器案例 `r98-biology-tables-live-v3/`。前两次失败及中间候选原样保留。

- `pnpm exec vitest run --maxWorkers=1`：167 文件、1957 测试通过；共享契约构建、`pnpm typecheck`、Web 构建退出 0。空白表头回归先失败、修复后通过；最终文档检查见同根 `r98-final-docs-check-v2.log`。
- 原生 `storage_state(indexed_db=True)` 恢复历史状态，只确认精修第 4、21、27 题。最终三次真实校验模型调用各一次接受；此前六次字段失败，合计九次，不计作新增语料。其余 24 条成品逐值不变，原题及来源图片哈希不变。
- 实际下载两份 27 页 A4 PDF，各 6599920 字节，并核对本地导出存储记录。重开后的模型请求增量为零，逐页 JPEG 哈希相同；两个 PDF 文件哈希不同，因此证明的是整理缓存及页面内容复用，不是 PDF 二进制完全相同。
- 共享解析器验证全部 27 条成品的来源归属；三张数值表无图片资产，全批无整图来源资产。无损只读观察在 JS 内先序列化，避免 Playwright 把可选 `undefined` 观测成 `null`；未改动原生状态或缓存数据。
- 从真实 PDF 提取第 4、21、27 页，逐格对照原图，表头、行值与选项对应一致，无重复表格照片；第 27 页未复制旧解题推断。另抽查第 2 页必要曲线保留。成品中表格与选项仍有文字重复，不作已完成排版去重声明。

`r98-transcription-content-verification.json` 保存共享解析结果及资源元数据；`r98-pdf-review-pages.json` 绑定抽查的实际 PDF 页面。验收连接和浏览器均关闭，既有服务保留。

## 未验证项与剩余风险

第 7 题沿用历史人工“仅保留文字”确认，本轮没有新增人工去图，不宣称无人值守完成。严格模式此前仍有待核对项，本轮未重新验收；不推断其他学科、真机、答案正确性或所有图示的视觉完整性。

新规则及模型说明已实现于当前源码和独立候选，本轮未向现有服务部署，也未提交或推送。当前规则见 [PDF 子系统](../subsystems/batch-pdf.md)。
