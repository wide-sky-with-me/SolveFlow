# Android 存储与备份恢复验收

日期：2026-10-03 至 2026-10-04。

范围：Android SQLite 容量故障、强杀、备份分卷与系统文件选择器恢复。设备为 iQOO Neo9 / Android 16；故障测试仅使用独立 `com.solveflow.storageprobe` 的合成题目，期间正式应用维持 0.1.71 / code 72，未清库、强杀或读取模型凭据；修复包 0.1.72 的覆盖安装另行记录。

结论：修复原生文件异步复制缺陷，13 阶段隔离验收通过；未覆盖整机存储耗尽、低内存设备或 500 题规模。

## 变更与处理

`expo-file-system` 57.0.7 的 `File.copy` 是异步方法。恢复入口以前在复制未完成时立即打开缓存文件，真实设备把完整备份误报为“缺少结束标记”。现在等待复制结束后以只读句柄打开，复制期间取消也先等待再清理；3 项新增回归在修复前全部失败，修复后通过。

SQLite 初始化和读写抽为共享适配；文件选择器与独立测试使用相同导出/恢复函数。数据库名、版本及备份格式不变。故障注入仅在测试入口，产品包检查增加探针标识排除。

## 验证结果

### 故障与恢复

- 真 SQLite 容量上限触发 `SQLITE_FULL`：事务失败无部分提交，解除限制后可重试。
- 答案写入失败保留有界内存结果，阻止新任务；恢复保存成功，执行器调用仍为 1 次。
- 提交前强杀后事务回滚、完整性检查通过；解题中强杀后恢复为 `WORKER_LOST`，不自动请求模型。
- 导入 4 题时在第 2 题提交后强杀；重导入跳过 2 题、补入 2 题，最终 4 题且图片一致。
- 未保存答案强杀后内存内容丢失，重启正确标记中断，无伪成功或自动重放。这验证既有限制，不是无损恢复。
- 截断备份在写入前拒绝，取消恢复撤回本次新增，原有记录哈希不变；取消导出删除残片，缓存清理通过。

72 道合成题按正式阈值导出为两卷：132,236,820 和 18,891,112 字节，共 151,127,932 字节（约 144.13 MiB）。乱序恢复 72 题，重复导入跳过 72 题；全部题图、答案、收藏和诊断的 72 个 SHA-256 一致，两端 SQLite 完整性通过。这是容量测试，不代表 500 题上限或真实模型成绩。

该阶段耗时 327 秒，包含建库、导出、乱序及重复恢复和哈希检查；最高 PSS 采样 279,169 KiB（约 272.63 MiB），不能当作单次恢复耗时或连续内存峰值。

系统选择器另验证 63 题、一卷 132,237,028 字节（约 126.11 MiB）：Android 目录选择器授权专用空目录，vivo 文件选择器选回生成的文件，正式恢复入口导入后 63 个完整记录哈希全部一致。生成的外部文件删除成功，两个测试空目录和探针私有数据清理；独立测试包卸载成功。

SAF 阶段最高 PSS 采样 329,755 KiB（约 322.03 MiB）；530 秒包含手动操作系统选择器的等待，不能用作恢复性能基准，也不包含文件提供方进程内存。整套设备验收共 13 阶段通过。

### 命令与证据

- 新原生导入回归 + 原有导出/存储/备份：5 文件、31 测试通过。
- `pnpm exec vitest run --maxWorkers=4`：98 文件、839 测试通过。首次沙箱执行被本机端口/子进程 EPERM 阻止，未把失败当通过；允许本机测试能力后重跑。
- `pnpm typecheck`、`pnpm lint`、`git diff --check` 通过；原生导入变更不涉及界面布局，本轮未重跑浏览器交互全集。
- `pnpm test:android:storage:build` 构建独立离线 APK；设备命令使用 `--device=<明确设备> --with-saf`。日志与阶段 JSON 在 `.runtime/storage-acceptance-2026-10-03/` 和 `.runtime/storage-device-2026-10-03T15-44-27-626Z/`。
- 初始探针的数据库 URI、预期对象字段顺序、合成 JPEG 复制错误均已修正，失败日志保留；它们与实际异步复制缺陷分别记录，不降低断言。

## 未验证项与剩余风险

SQLite 页数上限不是填满整机文件系统；未测试物理 ENOSPC、突然断电、低内存设备或所有厂商/云盘文件提供方。内存采样不是连续峰值。无真实付费模型调用，不据此更新解题准确率。

依赖漏洞、发行签名和完整准确率仍按 [发布状态](../project-status.md) 跟进。本报告不代表全部生产条件已满足。
