# 中心考试弹窗宽度与页面布局检查

日期：2026-11-03。`feat/public-photo-web`工作区增量，未提交、未推送、未部署远程。范围是中心考试Web，当前语义归[控制台](../subsystems/managed-exam-dashboard.md)，不包含原设备应用和独立公网拍题页。

## 问题与调整

用户截图中的教师详情沿用600px普通表单宽度，题目、原始答案、当前答案和核验意见依次纵向堆叠，大屏上显得窄长。

[共用Dialog](../../apps/exam-web/src/browser/components.tsx)增加显式宽尺寸；[教师详情](../../apps/exam-web/src/browser/monitor.tsx)使用最大1040px，桌面题图/题目与答案/处理左右分栏，999px及以下单列。普通管理表单维持600px上限。顶部统计与导航收紧留白，原始AI答案折叠，当前答案和问题状态仍可直接查看。

[局部样式](../../apps/exam-web/src/browser/review.css)统一页边距、标题/按钮换行和窄屏尺寸，覆盖浏览器默认dialog最大宽度。开启弹窗时背景不滚动，关闭后恢复；未引入依赖、数据库变更或真实模型行为修改。

红色问题改到Dialog独立提醒区，滚动题目或手动表单时持续可见，不覆盖选项、焦点及输入框。移除[旧样式](../../apps/exam-web/src/browser/styles.css)中的悬浮背景伪元素，避免手机横向溢出；学生主页面的持久提醒逻辑保留。

## 验证环境与截图

Node24.19.0、pnpm11.7.0、Chrome；本机预览3190只读检查，隔离PostgreSQL17.9集成使用合成图和假模型。没有收费调用。

本机截图脚本`node .runtime/ui-layout/review.mjs`覆盖35个状态：看板、跟踪、待处理队列、用户、场次、角色、统计、大屏/原生全屏、教师详情/人工表单、新建用户/场次/分配/模板及下拉选项、学生主页面/题号导航/答案详情。尺寸1440×1000、1920×1080、768×1024、390×844，包含明暗主题；不将这些视口测试称为真机验收。

脚本检查页面及弹窗内部横向溢出、弹窗边界、背景滚动恢复、教师桌面分栏、页面异常。表格和长内容可在其内部滚动。截图在忽略目录`.runtime/ui-layout/screens/`，本地画廊`.runtime/ui-layout/index.html`；逐页查看实际截图，读取数据后再截图，不用加载占位证明完整页面。

## 失败记录

第一次脚本因“待处理题”同时有h1/h2而定位不唯一，修正为一级页面标题。随后手机检查真实失败：dialog-body宽335px、scrollWidth338px，来自提醒背景伪元素。定位并修正布局，没有放宽溢出检查阈值。

截图核对又发现手动表单被悬浮提醒遮住前几个选项，已将提醒与滚动内容分离。另有早期统计、用户和学生答案截图拍到加载状态，脚本改为等待对应数据/弹窗后重拍；这些是截图脚本问题，不记录为产品加载失败。
