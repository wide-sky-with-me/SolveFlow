# PDF 失效追踪与公式释放边界

日期：2026-10-18。

范围：R63；Linux、Chrome 154.0.8037.97；真实照片批次的本地缓存副本；R60 私有控制产物及单变量公式候选。原生追踪、迟到字体模拟、普通恢复导出分别记录。现有 3100 服务仍是 R48，未部署新产物，也未重新打包原生应用。

结论：已修复块公式的已释放回调先读 `clientWidth` 再检查清理标志的问题。隔离真实浏览器重现旧代码的迟到读取，候选消除该读取，取消后的完整恢复通过逐页保真。原生失效追踪增加了节点及调用位置证据，但最大重布局没有调用栈，尚不足以确认整批来源树/打印帧的具体昂贵语句，生产流畅目标继续开放。

## 变更与处理

[块公式](../../apps/mobile/src/dom/math-text.tsx)只把已释放检查移动到第一次几何读取之前；[回归测试](../../apps/mobile/src/dom/math-text.test.ts)覆盖迟到字体、已排队尺寸通知、同节点替换及正常测量。保留初始宽度读取、同宽去重、字体就绪后的强制重测、字号上下界、溢出判定与观察器断开，不加入产品等待，不移除字号赋值。

失效追踪由冻结 R62 驱动派生，在一次可信取消的结束标记后立即停止；后续完整恢复不追踪。周期 CPU 采样及系统追踪未启用；原生事件调用栈收集内部会使用 V8 采样，因此不是零开销观测。先用合成节点验证所需事件和栈，再在真实批次中要求无丢失、完整时钟标记、正确渲染线程及可核对的 VM 脚本。方法沿用[浏览器时序报告](2026-10-18-pdf-native-timeline.md)，本轮不做延迟对比或 CPU 归因。

## 诊断结论与失败纠正

A 的最大初始子帧/主文档 Layout 约为 117.689/98.510 ms；B 约为 90.400/85.907 ms。它们都没有原生调用栈，前序成批加入布局树只构成时序关联，不是独占因果证明，也不是 DOM 节点数量。主文档公式末次边界读取在 A 有约 5.464 ms 的真实 Layout 栈；B 的公式字号赋值也有原生失效位置，但没有证据说明所赋值与旧值相同，因此未采用省略重复赋值的猜测。

取消后失效事件在整窗栈统计中占多数，主要关联 `frame.remove` 与 React 删除。分析已按输入请求前、输入排队、点击前及点击后分段，避免把清理开销归为来源构建。主文档身份来自初始 CDP frame tree，子帧身份来自原生父子记录与唯一创建探针；弱引用已收集时仅称“初始直接子帧”，不把源码标题写成运行时观测。

最初分析要求整个 trace 全部闭合而失败；原始审查确认只余开始于结束标记之后的调度器范围，现仍硬性要求窗口内范围完整、无失配结束。随后标题断言因弱引用已收集而失败；保留失败日志，使用可核对的父子图，不伪造标题。原始 trace 不裁剪，UTF-16 原生列号按实际 VM 文本解释。

迟到字体探针前两次预检错误预设两个节点而超时；第二次保存的真实计数为一个字体读取、一个公式节点。修正只涉及诊断门禁：以实际隐藏来源 DOM 的全部公式为独立覆盖集合，要求每个节点均被测量、取消后全部断开；控制迟到读取数必须等于该集合大小，候选必须为零。未删去释放断言或放宽产品超时。初始探针、两次失败、最终驱动和各自哈希保留于原目录及后续来源清单。

## 未验证项与剩余风险

单变量私有主脚本不是一次新 Expo 全量构建；它证明此 guard 在真实 React/DOM 和现有管线中的效果，未代表当前源码所有累计改动已部署。现有服务主脚本仍为 `c6742e0434dcc981b7ba5eec81f6cc033f8c2a0bb0bacea797dee95ad58d0bdf`。

本轮没有证明这个释放边界是初始输入长尾的主因，也没有 INP、FPS 或整体提速结论。来源首段、首个打印帧的同步长尾仍需继续定位。完整内容模式/份数/字体与浏览器组合、长负载、真实设备、原生新包及物理打印仍分别待验；[发布状态](../project-status.md)继续保留生产限制。
