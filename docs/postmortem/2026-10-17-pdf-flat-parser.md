# PDF 协作解析扁平状态机复核

日期：2026-10-17。

范围：沿用[监听候选](2026-10-17-pdf-lifecycle-observers.md)的 Web 下载链路，只缩减协作主树的递归生成器委托。源码和原生依赖补丁已接入隔离构建，旧服务未替换。

结论：结构、原生组件和整批保真通过，但本轮扁平候选中位比旧服务高 4.25%、比监听候选高 0.36%，未证实吞吐收益。继续隔离，不替换服务或宣称生产完成。

## 处理与边界

[生成器](../../scripts/generate-html2canvas-lifecycle.mjs)从固定原库语法树提取节点处理主体，仅将递归调用换成 WALK/ASSIGNED 帧。仍是单个遍历生成器，外层 async 驱动、每 64 次 next 让步、nextSibling 快照后的入口检查点均保持原样。帧转换不计节点，assigned 子树逐项延迟进入，不提前读取兄弟、firstChild 或整批索引；flags、初始 root、裸 slot 读取及 shadow 优先级保留。原同步 parser/helpers、首页和嵌套 iframe 同步路径、12 方法/95 恢复检查、取消优先及释放接口不变。

兼容 oracle 是独立冻结的旧协作算法，不是候选自比。原库 slot 分支的 forEach 固定长度并跳洞，旧协作候选使用 live length 且不跳洞；本次保留后者，不混入 composed-tree 或数组语义修复。原生 assignedNodes 对当前题页的影响尚未证明。选择及代价见[既有提案](../../.agents/notes/proposed/storage/2026-10-17-pdf-render-lifecycle.md)。

## 诊断与整批对照

剖析当前监听候选的 CPU1 冷首份完成 27 页。按实际 VM 的 UTF-16 源码范围分类，主树解析祖先采样权重约 641ms，其中生成器运行时 self 约 8.6ms；`r53-parser-profile-analysis.json` 保留原始负 delta 计数与其它两份历史诊断。权重不是独占计时，归类可能遗漏内联/native 工作；不把静态复杂度当作完整回退根因或可追回耗时。

独立核验 8 份同题集 PDF 的 216 页可见 JPEG/绘制指令，以及 27 页 RGBA 对照，一致；24 次可信取消终态、无成品及后续恢复通过，模型/外部调用和页面错误均为 0，缓存与服务身份不变。完整结果为 `r53-verification.json`。

## 采用条件

工作量下降不等于整批收益，且保真只覆盖同一题集。本轮保持旧服务，继续定位归属检查和同步构造/绘制岛，再扩展长负载、多样题型、整本回退、跨浏览器与实体打印。`archive-source-r53.mjs` 核对冻结前版及当前源/副本摘要，证据入口为 `r53-source-manifest.json` 与 `r53-summary.json`。
