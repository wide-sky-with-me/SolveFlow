# 教师端题图十秒延迟排查

日期：2026-11-06。范围：腾讯云HTTP IP18443入口，用户反馈缩略图与放大图均慢。只做诊断，不修改部署、容器资源或考试数据；登录和读取审计沿既有逻辑记录，诊断结束注销自己的会话。

结论：原图公网传输约16秒已复现；清晰预览约2–4秒。缩略图本轮HTTP约0.1秒、真实页面选题到可见约1.1秒，没有复现其十秒。HTTP入口容器同时存在明确内存压力和交换换页，可能造成间歇卡顿，但本轮不能证明它是用户每次缩略图慢的直接原因。

## 同图分段计时

诊断时有3个在线账号、2个未完成答题任务。读取同一张最近已上传题图，curl输出丢弃至`/dev/null`，不保存真实图片。服务器回环和公网路径走相同HTTP API、权限及私有对象存储。

Chrome独立诊断会话使用现有管理员的同款监控组件，只允许读取及本次登录/退出，禁止考试写入和推理请求。从已打开页面选题到详情约0.534秒、缩略图可见约1.112秒；缩略图请求本身约0.595秒。弹窗清晰预览约1.08MB，下载3.951秒。未再下载原图，页面错误0。新浏览器首次页面加载16.456秒，单独记录，不将其算成缩略图时间。

## 容器资源与代码

HTTP API配置内存上限384MiB。最初`docker stats`显示367.2MiB，占95.63%，CPU约0.31%；worker和主API没有相同内存占用。随后从宿主机读取cgroup，避免诊断进程占用应用容器配额：4秒内内存从385,097,728升至402,526,208字节，上限402,653,184；交换占用约162–178MiB，重大缺页增加1139次，内存max事件增加28次。没有OOM或OOM kill。宿主机仍约1.4GiB可用，不能把局部容器配额压力说成整台机器内存用尽。

首次容器统计包含不存在的旧存储名，故失败；改用四个已确认的应用/数据库容器名。容器内Node读取也会增加诊断内存，因此以上持续换页结论采用宿主机读取结果。

代码核对：教师小图请求独立`thumbnail`，不是原图；弹窗先读`model`清晰预览，放大后才读`source`。弹窗有受权HEAD复查的会话Blob缓存，原生缩略图未使用该缓存；HTTP仍是`private, no-store`。当前预览复用高质量答题图，约1MB仍需完整下载后解码；缩略图和原图不能用同一个体积原因解释。
