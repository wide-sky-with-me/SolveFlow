# 整理默认思考耗尽输出与字段完整性故障

日期：2026-10-14。用户 Windows 出现“题目整理返回了无效内容”，区别于此前 Esc 取消故障。原入口 `https://192.168.100.84:3130/` 保持不变。

## 实测与调用账本

每次真实调用均另行征得用户同意，累计四次，均只含恢复包首条记录的主图及补图共四张。未跑整批或自动重试，隔离浏览器不修改 Windows 存储。

1. 首次采集：浏览器没有保留可读 SSE 体，诊断失败，仍计一次调用。服务日志 08:37:47 UTC 完成、1786671 字节、55061ms。
2. 第二次：转发前在内存分析，HTTP 200、1773946 字节、finish_reason=length、completion_tokens=8192、正文3271字节，JSON失败。配置16384被[适配](../../packages/agent/src/pi/batch-print-layout.ts)隐藏压到8192。
3. 移除隐藏压限后的真实验收：3572204字节、length、16384 tokens，正文0字节。仅提高上限仍失败，默认思考耗尽全部输出额度；没有宣称成功。
4. 用户同意仅整理请求关闭思考的对照：236117字节、stop、1134 tokens、正文3877字节、思考块0。JSON有效，仍有空 sourceNumber 和缺少标签的选项图框两项字段错误。

诊断不持久保存模型原始响应或思考文本；私有输入副本、临时编译模块已删除，响应内存服务已停止。第四次响应经内存传递到独立进程，使用当前实际编译适配回放通过，模型请求回调1次、外部调用0、题目1。独立进程避开诊断进程旧模块缓存，未复制模型正文到文件。

## 最终修复

仅整理任务克隆配置 profile 并关闭思考，沿用已选协议与配置输出上限；不改解题设置，不换模型，不加自动重试。阶段对齐共享设备时限，64KiB正文、输入大小、题目/图源身份校验与取消优先保持。

模型读路径把空可选题号视作未填。无标签选项图只在其它结构、边界与唯一性均有效时保留对应原图及现有核对警告，不猜标签。严格 schema 与持久数据读取不放宽；无效边界、重复图框、陌生图源、未知字段继续失败。保留图仍可能需手动归属，严格试卷不冒充就绪。
