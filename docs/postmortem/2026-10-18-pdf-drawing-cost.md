# PDF 字体度量与画布初始化复核

日期：2026-10-18。

范围：沿用[画布归属复核](2026-10-17-pdf-canvas-provenance.md)的真实已存 27 题，Chrome 154.0.8037.97，源候选仍为窗口读取优化版；没有新增模型调用。CPU、几何、RGBA 与独占计时分开执行。

结论：字体探针隔离存在数值反例，淘汰。画布先定尺寸再获取上下文通过整批保真，两个镜像耗时均下降，但输入尾部未改善；仅保留隔离候选。产品源码、原生补丁和服务产物均未替换，仍未通过整体生产流畅度验收。

## 变更与处理

原生 CDP Profiler 请求 1000 微秒采样，不启用旧驱动的 busy-loop 标记或预热。20,266 个样本中，实际执行 SDK 的 `parseMetrics` 与 `CanvasRenderer` 构造函数分别出现约 1818、925 ms 的 self 加权样本。AST 位置与函数指纹已核对；该数值不是精确独占 CPU、长任务归因或收益，约 6486 ms 的 `(program)` 仍未分解。

字体实验从原方法提取两个候选：同文档 `contain:layout` 并修正 middle 坐标，以及绝对定位到零点；不跨实例缓存、不换测量文档。实际 Chrome 的 63 个字体/几何组合中，分别有 3、21 项不等；每项前后原方法均稳定。分数像素前置内容下 serif/16px 的原 middle=8，候选均为 9。普通场景通过并不证明位置语义等价，故未生成产品补丁。

另一候选仅将 `CanvasRenderer.getContext('2d')` 移至自有画布尺寸设置后，不改尺寸、质量、字体或调度。UMD/ESM 在移除该赋值后整棵打印 AST 相同，公开类型相同，原 12 方法/95 恢复点保留。两臂均从同一 UMD 源、同一 Metro 工厂参数和同一 esbuild 选项生成；未把私有最小化响应修改当作正式接入。该顺序变化的成本由实验判断，不宣称已证明物理位图分配机制。

## 验证结果

证据在 `.runtime/pdf-production-2026-10-16/`；关键入口为 `r56-context-generation.json`、`r56-context-source-proof.json`、`r56-font-fixture-chrome.json`、`r56-verification.json` 和 `r56-metrics.json`。

- `SOLVEFLOW_TEST_PDF_RENDER_PACKAGE=.runtime/pdf-production-2026-10-16/r56-html2canvas-sized-first-v1 pnpm test:pdf-render-lifecycle` 退出 0：49 项 Node 契约、98 项浏览器用例通过。浏览器直接覆盖候选 UMD/ESM/min；Node 契约不代替新候选的正式安装证明。
- `inspect-integrated-r51.py` 两次 `--cpu 1 --scenario cold --capture` 退出 0；独立校验均与冻结服务基线逐页 RGBA、可见 JPEG 及绘制流相同，共 54 页成对比较。捕获耗时不参与速度判断。
- 同一冻结驱动按对照 a、候选 a、候选 b、对照 b 顺序独占运行，`--cpu 4 --scenario interactive`；a 到达点为 80/700/1800/4200 ms，b 为 250/1100/2600/4800 ms。每臂 8 次可信取消后均能正常完成整批，事务落盘、文件缺席、通知收尾与既有资源门禁通过。
- 新生成 6 份 PDF 共 162 页均与固定参考的可见 JPEG/绘制流相同；独立校验计数 189 页另含复用的 27 页冻结基线，不重复计作新样本。缓存前后哈希不变，实际 VM/分发字节对应，模型、外部请求及页面错误均为零。

对照两次成功耗时为 18840.2/17997.8 ms，候选为 17607.3/17794.1 ms；镜像配对下降 6.54%/1.13%，中位数 18419.0→17700.7 ms（-3.90%）。成功窗口最长任务为 352/313→321/286 ms。但各臂八点中的最大输入等待为 197.0→307.6 ms，点击到落盘最大值为 253.8→154.2 ms，点击到 UI 被观察为终态最大值为 589.7→411.4 ms；这些是不同阶段的描述性样本，后两项改善不等于输入或实际呈现流畅。

首版采样分析因两条 -1 微秒原始 delta 失败，日志保留；后续累加原始时间戳再排序，保留全部样本和异常记录，不取绝对值或丢样本。首版函数指纹误把引号风格当语义而失败；改用 AST 精确检查 2d 调用、fontMetrics 字段及四个 offsetTop 访问后通过。首次归档又因 Node 摘要前缀假设失败，改为解析实际摘要，仍要求 49 项全部通过、零失败及 98 项浏览器通过。失败与复测日志保留，未改保真或性能门槛。

## 未验证项与剩余风险

每臂仅两份镜像成功样本，吞吐改善尚未转为正式 pnpm 登记和 Expo 构建；输入尾部也未通过流畅度判断。本轮未跑新正式构建、类型/完整单元回归、其他浏览器、实体打印或完整副本/ZIP 组合；没有新 UI 改动。

沿用驱动的正常编码画布与 frame 门禁不等于重新执行对象级归属审计；[此前归属结论](2026-10-17-pdf-canvas-provenance.md)不直接嫁接到新构造函数。CPU 诊断、RGBA 读取、几何夹具均不作延迟证据；历史首页差异的根因仍未闭环。本次不修输入控件字体参数错位的静态发现，避免混入单变量性能实验。

下一步继续定位取消前的输入长段，再决定是否将尺寸前置接入[源码级提案](../../.agents/notes/proposed/storage/2026-10-17-pdf-render-lifecycle.md)。当前语义与采用状态见[项目状态](../project-status.md)，历史回放不代替生产验收。
