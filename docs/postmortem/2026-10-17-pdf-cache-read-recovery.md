# PDF 缓存读取故障的原位恢复

日期：2026-10-17。范围：本机3100的Web构建、隔离浏览器故障注入与真实批次副本；不是全平台或生产完成声明。前轮[初读与未解答纯文字恢复](2026-10-17-pdf-read-and-extraction-recovery.md)保留原证据；当前运行语义归[批次PDF](../subsystems/batch-pdf.md)。

## 缺口与修复

有效整理内容仍在缓存中，首次读取暂时失败时，界面只提示使用已保存内容；原“整理题目与图示”按钮又依赖模型配置。无配置时，用户缺少直接找回已存题干、裁片与手动调整的入口。

这不是已证明的重复收费缺陷：源码与已有单元测试确认，普通整理会先恢复缓存，读失败也会中止而非盲目调用模型。问题是免费读取被配置门槛挡在界面之外。

[状态钩子](../../apps/mobile/src/components/use-batch-pdf-export.web.ts)新增独立失败标志与读取操作，[面板](../../apps/mobile/src/components/batch-pdf-panel.web.tsx)在反馈附近显示“重试读取整理结果”，无需配置模型。沿用现有工作锁与取消，使用当前快照、题界及内存状态恢复；成功才同步来源、图示和调整，失败或取消继续保留入口。已有脏记录须先补存。

没有重建题目数组或初读快照，避免触发副本初始化；没有图像重加工、新导出任务或显式整理保存。缓存适配仍会更新`metadata.usedAt`，所以“无正文写入”不等于整个IndexedDB零写入。未改变事务确认边界、缓存格式或模型配置。
