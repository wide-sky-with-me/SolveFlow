# 导出失败反馈与重试可达性

日期：2026-10-15。

范围：原本机 `http://127.0.0.1:3100/`、Linux Chrome，桌面／窄屏隔离回归；真实批次从独立 QA 浏览器复制到新上下文。只更新 Web 产物，不提交、推送或更新 Mac、原生应用及全局配置。

结论：生成、成品保存及整理缓存保存失败后，原报错会随长副本列表离屏。现已在操作结束且有错误时定位报错并接续键盘焦点；88 项定向浏览器回归及真实批次短屏恢复通过。保持原错误语义、资源门禁和重试职责，不将本轮局部修复当作整体生产验收完成。

## 复现与修复

滚到二十份副本列表末尾后，分别注入打印文档创建失败、成品文件存储配额异常、整理缓存配额异常。三条路径都能生成报错，但其视口交集为 0；仅检查可见 DOM 的断言遗漏了离屏。

在 [BatchPdfPanel](../../apps/mobile/src/components/batch-pdf-panel.web.tsx) 用独立可聚焦容器承接原有错误提示；仅在非忙碌且有新错误时，在布局阶段定位该容器。不主动定位成功消息，不改变正在进行的进度或用户的裁图编辑位置。原 `alert` 仍只保留一处，没有增加新的 live region。缓存保存失败后按 Tab 可抵达“重试保存整理”；屏幕阅读器的实际朗读未验。

成品保存失败仍由导出记录中的“重试保存”恢复；不自动新建任务或重复绘制。打印文档创建失败后可重新生成，旧失败任务不伪装成功。整理缓存保存重试只持久化已有结果，后续整理只接续尚未完成的题目。

本轮未调整图片处理、PDF 排版、缓存版本、文件上限、模型路由或任务终态。

## 探针校正

最初的编码故障探针没有命中实际打印绘制，导出反而成功，因此不是产品失败证据。打印内容存在独立文档边界，主页面的画布原型或初始化脚本不足以证明实际绘制已被拦截。保留两次未命中的记录，不把它们计为缺陷或通过成绩。

最终改为在已核对的打印入口中仅令首个 `contentDocument` 读取返回空，并校验报错与打印 frame 清理。保存重试使用主文档创建 frame 的正计数作参照：先证明确有生成，再确认保存重试没有新建打印文档，不以未命中的零画布计数证明复用。

有效失败回归证据：`.runtime/pdf-production-2026-10-15/e2e-feedback-r12-red-v2/` 的两类保存故障桌面／窄屏，以及 `e2e-feedback-r12-frame-red/` 的打印创建故障，均在完整视口断言失败。未命中的探针保留于 `e2e-feedback-r12-red/` 和前一目录对应编码场景。

## 边界与后续

聚焦错误只保证新失败能被发现，不将报错固定在屏幕上，也不自动处理用户随后主动滚动。生成失败仍可能需要用户调整设置；成品或整理缓存的保存失败有不同的恢复入口。关闭页面会丢失尚未落盘的临时成品，保持既有提示，不自动重放。

本轮不宣告整体生产验收完成。成品保存失败仍需进入导出记录，可继续缩短恢复路径。照片残边、邻题碎片、透视、持续负载和实体打印仍待验证；上一轮的[陈述与容量验收](2026-10-15-pdf-statement-capacity.md)保持原范围和结论。
