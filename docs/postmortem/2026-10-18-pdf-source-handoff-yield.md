# PDF 来源交接让步与资源就绪阶段复测

日期：2026-10-18。

范围：以[资源期限修复](2026-10-18-pdf-resource-handoff.md)的实际 Web 构建为基准，在隔离路由比较来源就绪后一次原生任务让步与透明对照。本机 Playwright Chromium；固定缓存、答案纸面、27 题、单份。没有改动产品源码、现有服务、scale、JPEG 质量、原图或模型调用。

结论：保真及取消门禁通过，但交叉收益不稳定，候选继续保留而未接入。输入长等待仍存在；阶段跟踪将后续调查收窄至资源就绪过程，不代表已定位其中的同步计算。生产流畅度未验收。

## 实验边界

生成器核对基准主包 SHA-256 `4206fcfd529eb21fcf08042dca32dbd7b2ff87550c02e23b31ac1c722f3f96c1`。仅在原 bounded 来源等待内部包装工厂结果，来源完成后执行原取消检查、一次零延时任务及再次检查，再交回原元素。对照保留原值和 Promise 身份；递归去掉包装后，原 Metro 工厂语法树一致。首屏绘制生命周期未改，见[提案](../../.agents/notes/proposed/storage/2026-10-18-pdf-source-handoff-yield.md)。

原始像素采集先单独执行；正式计时按预先记录的 ABBA、BAAB 顺序，各臂四个独立浏览器组。A/C 的取消延时为 80、700、1800、4200 ms，B/D 为 250、1100、2600、4800 ms，每组另有一次完整导出。延时从驱动取得可用取消按钮后启动，实际到达位置由可信事件与来源时点核对，不假设相同延时必然落在相同阶段。

计时使用 CPU 4×，无原始像素回读、CPU 采样、强制 GC 或并行的本会话构建、单测、诊断、子代理；普通宿主及原服务仍运行，不是整机隔离。静态核对驱动后，在结果分析前补记点击排队与按下至点击间隔；未改变采样顺序、主指标或取消门禁。

候选四次输入在来源就绪前已处理，另十二次在让步结束后才请求输入；本组原生取消没有落入让步窗口。候选最慢输入排队 246.7 ms，其输入请求晚于让步结束 18.2 ms。因此最大值下降不证明让步已消除卡顿，也没有稳定的整体收益证据；这些值不是 INP 或实机帧率。

## 保真与阶段诊断

对照、候选的原始像素各 27 页；交叉计时另产生 216 页，共 270 页 JPEG 与绘制流逐页门禁通过，其中 54 页另做严格 RGBA 比较。32 次可信取消的状态、无成品、缓存及已观测资源门禁通过。实际私有包抽出的让步钩子另通过六个受控任务队列案例，覆盖对照身份、直接元素、待定来源、让步前后取消和来源失败，无未处理拒绝；它们不替代产品 owner 与期限契约。

交叉计时结束后，另用候选派生建帧语句跟踪包：只加同步时点与透明返回包装，未新增 await；反向去除标记及参数语法所需括号后，原工厂语法树一致。新增一组 700 ms 可信取消及完整导出，27 页 JPEG/绘制流通过。此诊断不混入交叉性能结果；总计 297 页实验成品、33 次可信取消，严格 RGBA 范围仍为 54 页。

诊断取消的输入等待为 229.3 ms。正文克隆、追加及邻近语句仅覆盖其中约 35.8 ms；其后 193.5 ms 落在尚未闭合的资源等待语句，取消使该语句经异常路径退出。成功任务中同一含 await 的语句跨度 297.4 ms，最终尺寸与适配的同步返回表达式为 41.0 ms。异步跨度及未闭合区间不是 CPU 归因，不能据此宣布字体、图片或某条同步调用是根因。

首次跟踪生成被严格语法树门禁拦下：返回逗号表达式作为包装参数时，打印器增加必要括号。修正仅反向识别该包装所需括号后复测通过；原失败日志保留。分析器另修正含 await 的条件语句识别，并显式列出取消导致的未闭合等待，避免把资源跨度误记成同步耗时。

## 证据与命令

私有证据根为 `.runtime/pdf-production-2026-10-16/`，保留 `r60-measurement-plan.json`、生成器及各版本日志、每次浏览器结果和实际 VM 脚本、`r60-verification.json`、`r60-source-yield-timing.json`、`r60-source-hook-verification.json`、`r60-frame-trace-verification.json` 与 `r60-frame-trace-analysis.json`。源码、证据和前轮冻结校验另由 `r60-source-manifest.json`、`r60-evidence-manifest.json`、`r60-summary.json` 记录；浏览器配置副本不列入证据清单。

浏览器驱动使用 `inspect-source-yield-r60.py`，先执行 `--help`，按计划逐组运行 `--mode integrated --cpu 4 --cycles 1 --scenario interactive --arrival-ms ...`，分别指向私有对照/候选目录。严格校验用 `verify-source-yield-r60.py`；跟踪另用 `inspect-frame-trace-r60.py` 与 `verify-frame-trace-r60.py`。交叉链、钩子验证及修正后的跟踪链退出码均为 0，首次跟踪生成退出码为 1。没有调用模型，没有用旧页数算作新成品。

## 后续范围

继续保留来源让步候选，不自动接入，也不从本样本推断普遍变慢。下一步单独区分资源就绪回调中的字体 getter、图片解码与触发布局；一项变量一项变量验证。正式采用仍须补 owner、期限、计时器和晚到来源的完整契约，以及实际让步窗内的原生取消。

阅读、纯题、多份及字体未加载分支未在本轮重验；跨浏览器、长负载、真实设备和物理打印也未覆盖。资源结论仅限观测到的 frame、编码 canvas 和通知收敛，不等于所有类型 canvas 或物理内存已释放。现有服务保持原样；本报告不证明当前服务已包含后续源码修复。
