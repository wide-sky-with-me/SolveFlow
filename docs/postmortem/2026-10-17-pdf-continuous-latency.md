# PDF 连续取消、自然资源与响应采样

日期：2026-10-17。范围：本机既有 `http://127.0.0.1:3100/`、Chrome 154.0.8037.97、1440×1000 隔离上下文。主对照为正常 CPU 与四倍降速，各一个上下文、两个连续循环；每循环依次执行早取消、晚取消、恢复单份导出。全部使用同一份已保存的 27 题校样，不是多个独立批次。

结论：八次可信指针取消均持久化为 cancelled，无成品和下载；随后四次恢复真实下载 108 页 A4，实际显示 JPEG 逐页等于当前校样。自然撤销后被登记的弱引用目标均不再可解引用，主页面连接 frame 回到一个。降速恢复仍观察到最长 1122ms 的主线程任务，整体生产流畅验收未完成。本轮没有产品、UI、依赖或构建改动，没有部署。

## 方法与来源

沿用[真实编码取消回放](2026-10-17-pdf-codec-cancellation.md)的来源副本、R38 校样副本及已核实的单路径可选字段运输修正；不打开原 QA profile，不覆盖原题、冻结缓存、旧 PDF 或失败运行目录。仅保留副本的 3100 来源并移除旧导出库，阻断业务模型和外联请求。

主包与磁盘、3100 实际响应逐字节一致，SHA-256 为 `5c88465e97728e76444a8939e5690773e6c3b3f1ba2946c087381cf028b0393b`。两臂实际驱动快照 SHA 为 `02f8838b889141b5a63d38746864625e2cf41a45ca552ca1c87a57b3a2f5cc07`，观测函数快照 SHA 为 `2216782ab3f17aea03f5b53698693b96e96e08d0894106cbcab2b2755a30e1d1`。后续控制器加固不反改这两份执行快照。

实际入口是[前台下载](../../apps/mobile/src/components/batch-pdf-export.web.tsx)经 manager、任务核心和[生成器](../../apps/mobile/src/local/download-batch-pdfs.web.ts)执行。没有拦截绘制模块替换渲染器，也没有扣留、替换或伪造原生 Blob/ArrayBuffer。包装原 `toBlob`、原 Blob 读取并返回原 Promise；观测会增加回调、Promise reaction、日志和 RAF 成本，故不是零扰动基准，不与旧报告比较版本收益。

取消按钮可用且取得实际坐标后，等待额外四次或十二次原生字节读取通知，通过 binding → Python → CDP mousePressed/mouseReleased 派发。没有冻结应用；期间应用可以继续执行。该条件采样不是任意到达时刻，也不保证绝对第 4/12 页。按原生通知触发取消与[旧分段计时](2026-10-17-pdf-cancel-timing.md)的页进度触发点不同。

canvas/frame 表只留 WeakRef，Blob/事务使用 WeakMap；不强制 GC，不保存 Blob、像素或 DOM 强引用。主要采样窗口内没有 CPU profile、断点、画布读回或 PDF 解码；成品解析和存储摘要放在循环及资源采样后。构建、其它浏览器测试与两臂采样顺序执行。与[历史订阅与负载](2026-10-15-pdf-render-subscription-load.md)的强制 GC 样本分列。

## 结果与窗口

下列成功时间从可信“下载 PDF”click 的捕获监听器到同任务 succeeded 记录事务 complete，包含生成及持久化，不包含点击前派发等待、随后下载读回/Blob 复制及驱动文件落盘。最长任务是与该区间相交的主线程任务完整时长；没有把交集外时间计入总阻塞。

| 条件 | 恢复样本 | click 捕获至成功事务/秒 | 相交最长任务/ms | 已观察 RAF 最大间隔/ms |
| --- | --- | ---: | ---: | ---: |
| 正常 | 首次 | 4.9931 | 128 | 116.7 |
| 正常 | 再次 | 5.0058 | 115 | 99.9 |
| CPU 四倍降速 | 首次 | 19.6130 | 698 | 683.4 |
| CPU 四倍降速 | 再次 | 23.0199 | 1122 | 1133.2 |

每个条件只有两个恢复样本，不据后一次变慢声称持续退化、GC 根因或稳定吞吐。RAF 仅为已采样相邻回调时间差，缺少起点至首帧及末帧至终点，不是完整最大冻结时长或显示帧率。

取消各有四个样本，下表为样本范围。所有时间均来自浏览器自身时钟；Python 两次 CDP send 的墙钟单列在原始数据，未跨时钟相减。

| 取消观测/ms | 正常 | CPU 四倍降速 |
| --- | ---: | ---: |
| click timeStamp 至捕获监听器 | 1.6–8.4 | 4.3–60.9 |
| 捕获至首个真实 abort 调用 | 0.1–0.3 | 0.0–2.0 |
| 捕获至同任务取消事务 complete | 22.2–29.7 | 131.1–199.6 |
| 捕获至下载可用已被驱动确认的上界 | 67.8–92.4 | 394.3–473.6 |

最后一行还包含协议、locator 可见/可用断言和观测延迟，不是最早 UI 恢复或屏幕呈现时刻。首个 abort 很快不代表后续事务、执行槽、DOM 和原生工作同时结束。Event Timing 每臂收到 30 条、未触及容量上限，但本报告不将它们归并为 INP。

每臂共 86 次真实 JPEG 调用、86 次编码通知、86 次原字节读取及通知；四次取消分别留下 4/12/4/12 个已编码页面，另有两份各 27 页完整成品。额外时间线断言确认这些 API 事件和同任务终态事务均位于对应窗口内，未发现旧标签字节通知污染下一轮阈值；这只是本样本证据。两臂所有下载/取消都核对可信 pointerdown、pointerup、click 三联事件。

取消记录没有文件，后续旧记录保持不变。四份下载字节与 IDB 文件摘要一致，108 页的页面尺寸、单个实际显示 JPEG、各页不同图像及校样字节相等均由独立离线解析核验。原题与准备缓存的在线摘要前后一致；没有另开浏览器重读已关闭的临时 IDB，不把在线摘要见证说成独立重开存储验收。业务模型请求、外联尝试、页面异常均为零。

各轮自然 used 样本并不单调，最终等待原有 30 秒下载 URL 撤销；两份 URL/臂均自然撤销，未加速产品时钟。初始和最终采样条件、保留产物和等待长度不同，V8/DOM 调用也不是原子快照，不计算内存优化百分比或无泄漏结论。

被观测编码画布在轮末均为零尺寸或已回收，所属主 realm iframe 不再连接；最终所登记 canvas/frame WeakRef 均不再指向对象。仍有未登记 realm、其它创建方式、第三方引用、原生/GPU 内存和进程 RSS 的覆盖缺口。两臂观测到的最大未送达 API 通知数均为一，不是原生线程数，也不证明全部渲染/解码工作 drain。最终仍有四个 documents，保留该值而非把顶层 frame 为一解释成所有文档已释放。

## 驱动失败、修正与清理

`load-r41-normal-v1` 退出 1：完成两次真实取消后，错误地在 URL 已创建时就断言 download 事件到达。改为在点击前注册 `expect_download`，保留原等待与断言，没有调整产品。

`load-r41-normal-v2` 退出 1：循环已走完，但末尾引用了旧脚本的 `__loadRows/__loadHash`，实际初始化只定义 `__r17Rows/__r17Hash`。统一到已注入名称后重跑，不补写通过标记；两份失败证据不计为完整验收样本。

静态审查另指出控制器异常清理缺口。后续加固给 CDP send、失败快照和关闭操作设置本地期限，取消并收束 dispatch task，保护已取消 future，使用 AsyncExitStack 独立关闭上下文和浏览器，并在最外层 finally 落盘结果。六项提取实际 AST 的协作替身检查通过，覆盖关闭失败继续清理、协议等待超时、迟到 future、任务收束和启动异常记录。替身超时加速只用于该离线检查，未改真实采样及产品期限；不等于真实 CDP 断链或 OS 强杀已验收。

清理加固后另跑 `load-r41-cleanup-v1`：两次真实取消后恢复一份 27 页 PDF，逐页 JPEG 等于校样，存储摘要核验通过；副本来源上下文、运行上下文、浏览器三个关闭回执均成功，命令链退出 0。其执行快照 SHA 为 `de9d1996b87e5e1ca9f9dda24ec8e682521d7f2029cc1a5d25cc8de421e86563`。这 27 页不并入上述正常/降速对照，真实 CDP 故障注入仍未验收。
