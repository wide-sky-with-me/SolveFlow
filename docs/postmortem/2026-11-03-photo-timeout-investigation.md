# WebKit重答提示超时的时序调查

日期：2026-11-03至2026-11-04（北京时间）。

范围：`feat/public-photo-web` 工作区，公网单图入口、合成题/假模型及隔离浏览器。真实付费调用0，未提交或部署；不修改中心平台、原生端或远程服务。

## 结论与证据边界

已稳定复现并修复两条等待异常路径：迟到的本地照片读取覆盖终态，以及联网恢复后仍等待旧状态查询。前者会让错误消失、页面重新等待；后者会延迟已有答案的显示。

原来的报错是自动化测试等待错误提示的5秒期限，不是DMX调用或服务端6分钟期限。最初失败发生在假模型场景，只有截图/断言日志；新增探针前没有完整时间线，不能百分之百反推其当时触发条件。以下根因结论针对本轮受控复现，不虚构原现场数据。

## 定位过程

先用元数据探针连续运行原场景20次，WebKit桌面20/20通过；从点击重答至出现失败提示约2.32–2.58秒，未捕获自然超时。事件包括HTTP起止、假模型起止、IndexedDB事务耗时、运行ID/序号、页面状态及长事件循环间隔，不记录照片、答案正文或密钥。探针只在测试夹具和浏览器测试中运行。

随后只延迟一次已经完成的照片读取回调，不阻塞存储写入、不拖慢模型或HTTP。手机、桌面两例均失败，原5秒断言保留。这是时序故障注入，证明旧读取晚到时的处理缺陷，不代表捕获了浏览器自然停顿。

手机例从第二次POST到达服务端计时：

| 相对时间 | 实际事件 |
| --- | --- |
| 1.575秒 | 假模型结束 |
| 2.095秒 | 服务端完成状态查询，返回200 |
| 2.160秒 | 本地读取到已保存的failed/seq3 |
| 2.188秒 | 页面显示错误，停止等待 |
| 2.565秒 | 迟到读取回写后，页面退回“正在识别”，错误变为0条 |
| 随后5秒 | 原断言超时；不是服务器仍在解题 |

数据来自 `controlled-before.json` 的手机附件。旧快照在元数据读取时保存queued/seq0，等待照片恢复期间，其他请求已经完成终态写入；之后无条件setRecord使其覆盖新状态。最后一次回退后没有新的活动事件，页面可持续停留。桌面同样复现。

另发现进度订阅总是重新读磁盘，而处理中状态只在引擎内存更新，因此画面会一直显示queued，不能据截图判断模型是否运行。

## 修正

[工作区](../../apps/photo-web/src/browser/main.tsx)直接应用引擎公开状态；异步读取经[运行视图合并器](../../apps/photo-web/src/browser/run-view.ts)按同一运行ID/序号前进，保留新重答和未保存结果，阻止终态回退及取消被覆盖。切题与运行时归属继续检查。没有增大超时、加速轮询或重发模型请求；取舍见[决定](../../.agents/notes/implemented/architecture/2026-11-04-photo-view-ordering.md)。

## 连网恢复的另一条路径

仅修正视图后，Chrome完整34/34；WebKit首次完整32通过、2失败：断网恢复后未在5秒内显示答案，以及后续一次页面初次导航被取消。证据保留为 `webkit-full-after.log`。导航失败没有证明与应用状态有关，不能冒充已由本次修复解决。

进一步受控挂起一次离线GET状态查询，恢复网络后仍等其AbortSignal。原实现只在两次请求之间监听恢复事件，查询进行中则要等原10秒期限；两例均超过原5秒断言。修正[恢复器](../../apps/photo-web/src/browser/remote-jobs.ts)：联网/回前台时中断旧GET，按原2秒间隔重查同一ID，主动取消仍优先，不重传POST图片。修复后2/2，10.51秒；这是恢复延迟的确定性缺陷，不能据此回填首次缺失的网络时序。

## 限制

没有原现场完整时序，不能断言任何一次慢响应都由同一缺陷引起。本轮不验证真实模型延迟、iPhone真机存储/相机、低内存或持续负载；Linux WebKit不替代真机。既有本机服务和用户数据保留。
