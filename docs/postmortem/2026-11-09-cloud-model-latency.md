# 云端慢题的调用阶段归因

日期：2026-11-09。

范围：腾讯云既有考试数据库，只读查询截至北京时间13:45；历史任务创建于2026-11-04 21:08至2026-11-07 10:34。线上仍为`20261108-53ee2a1`。未修改配置、重启、部署、重置账号或发起真实模型调用。

结论：历史4—5分钟慢题主要耗在首个主模型失败前的等待，随后重试或备用解题，再串行核验。最慢三题的首调用均接近240秒。服务端接收任务后的准备及其他非模型处理不足以解释分钟级耗时；不据此排除客户端上传和公网读图的独立延迟。

## 数据范围与口径

读取1080次任务、2351次调用：979次完成、5次待澄清、96次取消，全部为解题任务。耗时由任务创建到最终完成，包含解题及核验；分布以979次完成任务为分母，取消不混入正常答题速度。

通过HTTP试用、主API和worker的配置核对，三个实例使用同一考试数据库。数据关联后仍为1080条任务，无缺失调用、负时长、未结束调用或孤立调用；单个任务的模型调用时间无重叠，可以按阶段相加。首调用前耗时包含领取、图片准备和名额等待，不能单独称为排队时间。

## 慢题证据

9次已完成任务超过180秒，其中8次数学、1次阅读写作，全部发生在11月5日，也全部经历首个主模型调用失败。979次完成任务中，首调用失败后最终恢复的有40次。

首个模型均为`deepseek-flash-guan`；这三题随后由`gpt-6.1-sol`解题并核验。其余慢题多为同一主模型重试，不能全部称为备用切换。接近240秒与[现有主解题阶段预算](../../packages/contracts/src/agent.ts)吻合，但账本只记失败，不能直接将每次失败分类为某一种超时。

全部1080次任务从创建到首个模型调用平均0.134秒、最长0.611秒；979次完成任务扣除模型调用后，剩余处理最长0.899秒。最慢题首调用前0.277秒。分钟级延迟集中在调用期间，包含供应商响应、传输和本地消费响应流，不能只凭时长进一步拆成供应商内部排队或推理时间。

1146次DeepSeek调用中有115条失败，但其中包含学生取消；全部模型失败记录有88条属于已取消任务，不能把账本失败比例直接当供应商故障率。账本未写入token数，不能断言慢题源于长推理或较大token输出。

## 当前状态与处理方向

11月7日566次完成任务中位14.4秒、最长140.4秒；与11月5日的题目、使用者和模型路径不同，不能将差异当成某次发布的因果效果。11月8日部署后没有新答题记录，不能用这批历史证明新版本已解决慢题。

采样时无活动任务及近一分钟活跃账号；worker约95MiB/1.17GiB、CPU约1.15%，HTTP试用API约102MiB/512MiB。当前资源宽裕不代表历史时刻没有压力。

优先补齐首响应、无进展、断流、供应商错误码和调用标识，再调整无进展时的重试/备用接手时机。不能从总耗时推断安全的首响应阈值；需验证正常慢题不会被误中断。此次未更改模型、等待预算或并发。
