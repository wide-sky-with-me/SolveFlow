# PDF 绘制生命周期接入与整批复核

日期：2026-10-17。

范围：html2canvas 1.4.1 的 pnpm 补丁、Web 下载器、独立基线及本机 Chrome 的隔离构建。真实缓存副本为同一批 27 题，不调用模型。

结论：依赖和下载器已接入，原生组件与整批保真通过；但独占交互对照发现耗时回退与长任务不稳定，不采用候选。本机 3100 服务仍为旧产物，未完成生产验收。[前次源码候选](2026-10-17-pdf-source-lifecycle-adapter.md)只代表当时隔离范围。

## 变更与处理

资源挂起复现中，外部任务结束并不等于绘制内部资源立即释放。保留源 frame 后，旧候选的画布宽度仍为 300；释放资源 Promise 后才完成清理。新增每次绘制独享的同步释放登记：取消或到期时归零所属画布、移除克隆；正常结束先解除登记，成品继续交给原 JPEG 管线。旧 Promise 仍可挂起，迟到恢复须重新检查，不将尺寸归零表述为原生工作已终止。

[下载器](../../apps/mobile/src/local/download-batch-pdfs.web.ts)在建 frame 前检查 v2 能力；每次绘制建立独立文档归属和真实取消/期限闭包，绑定实际克隆。每份首绘保持同步解析，后续题页才使用 64 节点协作切片。scale、JPEG 质量、编码与容量门禁保持原值。

沿用 pnpm 原生机制登记[依赖补丁](../../patches/html2canvas@1.4.1.patch)，锁文件没有变更依赖版本。不存在手改安装目录或安装后脚本。[独立准备器](../../scripts/pdf-render-baseline.mjs)在临时独享副本中反向应用补丁，验证 UMD、ESM、min 及两份原 source map 的固定 SHA，避免已安装补丁后的自比；显式基线也严格校验。取舍与边界见[提案](../../.agents/notes/proposed/storage/2026-10-17-pdf-render-lifecycle.md)。

### 交互性能

独占执行旧版、候选、候选、旧版的 CPU4 回放；不运行其他构建或测试，不启用像素采集。每轮按独立控制器在 80/900/4000ms 发送真实取消输入，再完成整批导出。独立复核所有 6 份成品共 162 页可见 JPEG/绘制指令一致；12 次真实取消无下载、无成品，随后均成功恢复。`r51-final-verification.log` 与 `r51-verification.json` 记录逐次结果。

| 非采集性能样本 | 旧版 | 候选 |
| --- | --- | --- |
| 每组两次整批耗时 | 20.3513 / 20.1191s | 31.9146 / 26.7214s |
| 两次中位耗时 | 20.2352s | 29.3180s |
| 每次最长任务 | 590 / 602ms | 1177 / 467ms |
| 真实输入等待观测范围 | 6.7–265.5ms | 4.0–430.7ms |

候选的样本中位耗时增加约 44.9%，最长任务一轮恶化、一轮降低，暂不满足替换条件。没有据此宣称总体分位数或确定根因；历史私有响应补丁的性能不替代本次源码适配。

另建限定为单次冷启动、强制剖析且禁止 RGBA 的诊断入口，保留计时入口的剖析禁令。`r51-profile-candidate-v2.log` 退出 0，成品再次通过回放内逐页校验；不计入上表。`r51-profile-analysis.json` 的采样显示字体指标路径约 2.12s、文档归属检查自身约 1.10s，另有未归因 `(program)` 权重。它们是热点线索，尚不足以解释全部回退；后续需旧版剖析和窄范围变体验证。

## 未验证项与剩余风险

未替换服务产物；新构建的更多 UI、ZIP、多份、长负载、浏览器矩阵与物理打印仍需单独验收。组件合成期限不等于真实完整超时边界已穷尽；同步岛及根/单节点耗时仍存在，64 节点不是墙钟保证。此处的缓存固定样本和有限交互轮次不代表全部真实题目或设备。
