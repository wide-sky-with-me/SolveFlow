## 已确认的原因

1. 批量槽位直到校验结束才释放，有效答案也只在最终结果发布，造成答案和后续题目一起等校验。现已先落盘展示答案，三路求解与一路 FIFO 校验独立准入，校验池八份输入，满额背压，最多十一份常驻输入。
2. 补图此前只保存；用户随后点旧答案校验会使用旧材料快照。只读记录未发现提交材料 ID 与实际保存材料不一致，不能据此证明当时模型确实理解了图片。现提供“使用原图和全部补图重新解答”，明确创建新版本；旧答案继续保留。
3. Node 已允许 8MiB SSE，设备仍在 1MiB 截断。旧日志多次 HTTP 200 响应在约 1,049,000 字节处由客户端断开；目前两端统一 8MiB SSE/1MiB JSON，并将超限单独分类。它不能解释全部失败。
4. 真实复测发现主/校验模型生成满4096输出token后截断，属于输出额度耗尽，不是工具或时间超限。增加额度后补图校验成功，但生物复核仍在16384 token时截断。定向 Sol 对照得到有效校验结果，因此本地 Web 独立校验改用已配置 Sol，不扩展任意模型路由。

累计时间继续不限，阶段仍有限：自动主/备用各240秒，手动无备用主求解300秒；校验普通120秒、图示/化学150秒、独立选择及长文/分小问180秒。无备用自动阶段仅近期流进展可延长15秒，既有晚格式修复最多20秒；次数、取消和有限重试保持。

## 交互与安全边界

- 秒表由用户开始、停止、续计、重置；按题及图内题号保存。刷新继续此前手动开始的墙钟计时，不随模型自动启停，旁路计时未进入题目备份。
- 数字导航和速选格：绿色通过、橘色已答等待/未通过校验、红色失败/仍缺关键条件、灰色未答。选择边框不覆盖状态色。
- 题干充分而选项不全时先给结论并警告；不补造数字、选项或条件。校验同时检查正确性及evidenceStatus，不确定依据不能成为verified。
- 用户备用组优先，无备用时可由配置校验组接手一次；非政策追问可重判，仍缺关键条件才继续追问。纠错失败保留答案和未通过提示，不循环接手。
- 重启保留已落盘候选为未验证及WORKER_LOST；没有候选才恢复失败。严格旧客户端可能不支持新扩展，不降级覆盖。
