# ADR 0008：澄清、定向追问、题干更正与裁切

状态：接受。2026-09-14，用户在可用性评审后明确授权开始改进。

## 决策

1. Web 展示同题已保存的澄清与答案。新任务进行中、失败、取消或刷新后仍能查看旧答案；旧答案有各自校验状态，更正前结果明确标记供对照。
2. HTTP v1 增加可选 `context`：step（sourceRunId/stepId）、question（sourceRunId/number）、correction（sourceRunId/text）。引用由服务端检查 owner、session、结果与步骤/题号；不接受客户端传入候选或 verified。上下文进入幂等散列；旧请求不带 context 时散列保持兼容。
3. 新增不可变迁移 `0002_run_context.sql`，在 runs 添加可空 JSONB context，不覆盖旧消息或结果。部署先执行迁移，再启新服务。迁移逐份校验 hash，启动要求第二版迁移记录。
4. Worker 同时保存澄清问题、答案校验状态与教学步骤节选。最多9轮，历史 UTF-8 JSON 上限12KiB；定向追问时缩为4KiB，给所选步骤与当前补充留出空间。服务端解析得到的 focus 与完整最新 problemCorrection 同时进入 Solver/Verifier。它们仍是不可信学习数据，不能覆盖系统安全策略。更正后每轮重新走独立校验，不继承旧 PASS。
5. 裁切先在浏览器处理原始文件，再经过原有服务端真实格式/像素/EXIF/私有上传校验。保存后的图片保持不可变，可放大查看；改题干生成新 run。此次使用原生 Canvas、Pointer Events 和可键盘操作的边界滑块，不增图片库依赖。技术方案曾规划 react-easy-crop，当前矩形需求用上述原生能力满足，后续透视矫正等需求再评估成熟库。
6. 会话10次、owner滚动24小时30次和已保存100题的现有限制保留，分别返回 SESSION_LIMIT、DAILY_LIMIT、STORAGE_LIMIT，明确用户下一步；不改变无限金额测试模式或运行时间/工具预算。

## 边界与后续

本轮没有拆分每题独立任务或校验状态，没有引入整卷识别、题库、自动模型路由、任意代码执行。图示仍用原有受限协议；按步骤插图、复杂几何和单题重试属于后续结果契约工作。物理/化学等专项 Skill 与隔离数学服务须另行实现并验收，不将通用文字能力宣称为完整工具能力。

`problemCorrection` 表示最近一次用户补充/更正（可为完整题干或局部改动），后续继续携带；旧的更正与答复通过有界历史节选补充。用户连续提交多次局部更正且跨越历史裁剪边界时，仍可能需重新确认完整条件，未宣称无限对话记忆。
