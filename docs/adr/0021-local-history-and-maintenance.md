# ADR 0021 — 本地历史性能、备份恢复与请求额度

- 日期：2026-09-30
- 状态：已接受（用户授权按六项优化逐项实施）

## 决策

1. 历史摘要在 `LocalRepository` 内维护最多 500 项的内存快照，保存、收藏、批次改名和删除后更新并通知订阅者。队列状态变化不再触发磁盘全量扫描；用户进入历史页时仍允许强制刷新。批量恢复逐条读取元数据，不一次并发读取整批题图。
2. 同一个 SQLite/IndexedDB 文档库保存 `record.<id>` v2 元数据与 `image.<id>` v1 原图。首次保存或旧题再次保存时，在同一生产存储事务中写入两者；普通结果更新保留原图，不再重写 base64。读路径兼容旧 v1 整题文档，公开 `LocalRecord` 与 NDJSON 备份仍为包含图片的 v1。题图属于不可变的题目附件，更换题图必须新建题目。数据库表本身不变；v2 数据和超过十条的会话不保证旧版应用可读，不支持降级覆盖安装。
3. 本地单题额度分为最多 10 次对话（含首次解答、失败尝试）及最多 30 次辅助请求。辅助分类沿用共享 `isAuxiliaryContext`，不改变并发、取消、120 秒预算和已完成内容缓存。共享会话/备份读取上限扩为 40；保留的服务端提交额度不变。
4. 本地新增备份恢复。逐块读取最多 768 MiB 文件、单行最多 64 MiB；第一遍完整验证版本、结束标记、题数、标识归属、诊断归属、批量序号和 JPEG 字节数/尺寸，再逐题事务写入。已有题目 ID 跳过，保留本机数据；冲突的解答 ID 或批次位置拒绝。恢复不读取或覆盖模型设置/密钥，不发起模型调用；非终态记录转为 `WORKER_LOST`。操作失败或取消撤回本次已写入的新键，撤回失败明确报错。进程被强杀可能留下完整恢复的部分题目，重新导入将跳过这些题目继续补齐；不宣称整个文件跨进程原子。
5. Android 用系统文件选择器，复制到私有缓存后分块读，正常结束清理，下一次恢复清理崩溃残留；Web 用不可变 File 快照分块读。只使用已有 Expo 能力，无新依赖。导出也执行相同单行限制，避免生成自身无法恢复的备份。
6. 新设备校验结果必须报告已检查原图转录以及逻辑或运算，否则 PASS 转为 UNKNOWN。历史验证结果不追溯改写。此门槛识别检查不完整，不能验证模型是否诚实报告检查，也不证明误通过率降低。生产 Pi 循环、模型选择、独立验证角色均保持。
7. 固化 `scripts/test-android-pager.mjs`：从用户打开的已保存批次开始，指定设备/步数/方向，验证最终题号，保存版本、gfxinfo、内存及可选录屏。测试不清库、不提交题目。`scripts/test-verifier-regression.mjs` 默认只检查固定图片哈希与样例；显式 `--live` 才运行付费验证，全部结果包括失败保留。输出保存在忽略的 `.runtime/`。

### 2026-10-03 生产可用性修复

用户授权实施生产审阅发现的问题，本次补充不改变存储版本、备份 v1 格式、模型权限或 Pi 循环：

1. 最终结果写入失败时，设备引擎在内存保留已接受任务的结果，阻止新增解题和新题提交，并展示「重试保存结果」。重试只读写本地存储，不重新调用模型；失败不清除内存结果。已开始的其他任务可以结束，批量等待队列停止派发，尚未解答的已保存照片保留。保存恢复后不自动继续队列，用户明确选择「继续待解题」。取消与写入并发时仍保留取消优先语义。
2. 单条记录、收藏或批次名称的 JSON/版本/结构损坏，作为明确的数据问题登记并保留原始字节；不再阻断其他历史的读取与启动。存储读写故障仍报错，不冒充空历史。读取题目时才发现的坏图也通知维护入口。损坏记录继续占用 500 张额度。
3. 「记录维护」提供明确确认后的附加信息重置，以及从完整备份中单独恢复一条无法读取的题目。前者只移除损坏的收藏/名称覆盖值；后者先验证整个备份和其他可读取题目的编号冲突，再用一次事务替换选中题目的元数据、图片、摘要、收藏。健康题目不允许覆盖，事务失败保留原数据。已有诊断键不覆盖。其他损坏题目的未知内容不能用于冲突校验，仍原样保留；新补入诊断仅使用未占用键。
4. 导出先逐题规划，每卷最多 128 MiB、单行仍最多 64 MiB。规划只保留 ID/字节数，每次读取一题；输出时再次检查容量。每卷均含 v1 头部和结束标记，可独立恢复、乱序恢复，重复恢复沿用跳过已有题目。界面逐卷明确点击保存，取消/失败不推进分卷进度。存在无法读取的记录时，先显示未包含题数并要求确认，不静默把部分备份当完整备份；原始键损坏也计入未包含数量。

## 限制与验收

- 普通导入仍跳过已有题目，不对比新旧答案。选中损坏题目的恢复是另一个明确确认的入口；只能恢复到备份版本，未备份的较新内容无法重建。
- 未保存结果只在当前进程内保留，退出或系统杀进程可能丢失，界面明确提示保持应用打开。不能把内存重试声明为跨进程可靠落盘。
- Web 导出每卷仍需构造 Blob；128 MiB 是文件大小上限，不是内存峰值保证。未在真实手机上做磁盘占满、进程强杀或超 768 MiB 全库导出验收。
- 原图分离使结果写入变小，但已有旧格式题目首次读取/迁移仍需处理原图，模型输入仍需读取原图。
- 真机测试涉及固定设备、内容和录屏负载；默认报告指标，不根据任意阈值宣称流畅或零白帧。
- 真实校验外发需授权所使用的模型端点，不能用离线契约通过冒充准确率验收。
- 首次优化命令与实测见 `docs/LOCAL_OPTIMIZATIONS_0_1_63.md`；生产存储修复结果见 [可靠性记录](../RELIABILITY_REVIEW_2026_10_03.md)。
