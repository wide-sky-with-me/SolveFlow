# ADR 0011：Solver 每 run 提高到 16 轮

- 日期：2026-09-15
- 状态：已接受，用户明确要求提高轮次

## 问题与决策

实际失败记录在完成工具调用和第一次独立校验后，进入 revising，最终报 MODEL_LIMIT；相同输入重试成功。初次解答、工具后的模型调用、JSON 格式修复和修正共享原来的 8 轮上限。模型执行路径会变化，不能据重试成功认定第一次是供应商故障；失败记录没有保存计算参数或校验意见，不能进一步推断具体内容错误。

将 Solver 的共享上限从 8 调整为 16；Verifier 仍最多 2 次。所有模型派发通路统一容许合计 18 次，超过上限继续失败关闭。`packages/contracts/src/agent.ts` 定义公共常量，RunBudget、父进程授权、有限额度记账门、worker RPC 客户端和请求/响应 schema 使用同一来源。ProbeReport 扩大合法计数范围，旧结果仍可解析；内部 schemaVersion 保持 1，不改变 HTTP/SSE 或数据库结构。

保留 120 秒总时限、最多一次修正、一次 JSON 语法修复机会、工具总数 16（文件 8 / 业务 8 / 搜索总共 2）和 Verifier 单次最多 20 秒。增加轮次不会增加工具权限、取消内容审核或改变模型环境配置。费用默认无限，有限模式仍依据实际配置预占且为校验保留费用。更多轮次可能增加耗时和费用；这不是对复杂题完成率的保证。

## 验证

先补回归：旧实现下定向测试 8 项失败，明确触发 MODEL_LIMIT 和第 11 次 RPC 拒绝；完整测试进一步发现有限模式内部 request-spend-gate 的旧 10 次限制，随后一并修复。

验收覆盖真实 Pi SDK 的离线模型/工具循环在第 9 轮完成、跨阶段累计 16 轮边界、修复请求耗尽、有限/无限模式 16+2 请求、真实 worker 18 次授权与第 19 次拒绝、取消和监听器清理。测试供应商是合成实现，没有以此宣称真实模型复杂题通过。

最终命令、结果和本地服务状态见 [轮次调整验收](../SOLVER_ROUND_ACCEPTANCE.md)。
