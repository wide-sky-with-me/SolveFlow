# ADR 0009：以题目组织持续对话

状态：接受。2026-09-14，用户明确要求将追问及回复框在所属题目下面，以题目作为最终内容分区。

## 行为

- 每个明确识别的题目拥有一个容器：原解答 → 后续提问/回答/澄清 → 本题输入框。步骤追问、等待、取消、失败和重试也留在该容器内，不在页面底部追加游离的回答卡。
- 不同题目的输入草稿分别保存在各自组件中；发送一题不会清空另一题。已保存对话可刷新恢复；未发送草稿不持久化到浏览器存储。
- 以原始结果 runId + 题号识别题目，以 sourceRunId + 步骤id识别步骤；不靠模型重复输出的“第1题”标题猜测归属。回复的后续回复沿已有引用链回到原题，不创建新的题目分区。

## 协议与服务端

沿用ADR 0008的可空 JSONB context，不需要新数据库迁移。HTTP v1增加 `context.kind=reply` 和 `sourceRunId`；correction增加可选number，用于更正多题原始答案中的指定题目。旧字段与请求仍可读取。

`packages/contracts/src/question-thread.ts` 共用引用解析与题目投影：限制10层，拒绝循环、缺失及跨会话引用；API在owner/session授权后检查有效来源。对原始多题答案直接reply或无题号更正属于范围不明确，需选择题目。原始结果与独立校验不被投影覆盖。

Worker只向Solver/Verifier传入当前题目的历史、题内步骤节选和该题的更正；其他题的补充不覆盖本题。原图仍独立提供，模型每次仍重新校验。SYSTEM/VERIFIER明确单题追问不重答整页，不改变用途安全边界、Pi loop或模型配置。

## 兼容与边界

旧单题的连续无引用记录可合并展示；多题历史没有明确引用时保留独立记录，不按文本猜归属。旧显式题号且可完整无歧义分组的结果使用已有兼容解析器，现由前后端共用。

仍然遵守同一图片会话一个活动run、单会话10次及滚动24小时30次任务等已有约束；持续对话不意味着无界任务。没有实现每题独立并发或拆分整次验证状态。当前模型若自行回复无关内容，仍需依靠独立核验与评测，UI分区本身不是正确性保证。
