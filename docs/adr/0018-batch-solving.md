# ADR 0018：连续速拍与批量解题

日期：2026-09-21。状态：用户已授权实施及付费测试。

## 决策

新增“批量解题”入口。相机每次快门将题图规范化、保存到本机后加入后台队列，相机继续打开；相册也可逐张添加。单张建议拍一道完整题。批量每次最多并行处理3张、每批最多100张，本机总容量上限从100张提高到500张，不自动删除已有记录。保留当前图片处理上限及导出768 MiB上限；500张不意味着一定可一次导出。

批量复用 LocalEngine、Pi 核心和独立 Verifier：每张初次解答及后续普通解答自动校验，FAIL最多修正一次再验，120秒总预算保持；非PASS不能显示“已校验”。单独拍照依然默认简洁答案、手动校验。按需详细步骤/知识点请求沿用原流程，批量队列运行期间暂不插入按需请求。

LocalRecord / LocalHistorySummary 增加可选 batch（UUID、标题、创建时间、考试快照、拍摄序号1–100）；可选字段兼容既有 schemaVersion 1。每张创建时固定位置，不按完成顺序排序。题目正文增加可选 problem.sourceNumber（最多40字符），只摘录清晰可见的原卷题号，不猜测，也不作为路由ID。旧记录保持原样；历史搜索纳入已提取题号，多题图汇总各题题号。

“单独拍照”和“批量记录”分开。批量按组打开，复用既有题号导航、题图缩放、答案、追问、步骤及更正。页切换只保留当前照片组件，队列只持有ID及执行配置，避免全批原图进入内存。可删除整批，先停止相应任务，再删除记录。

Android 前台服务复用一个服务，按 runId 分别维护后台生命期、截止时间和阶段计时器；完成或超时一个任务不关闭其他任务。最后任务结束5秒后释放服务，给队列下一张交接时间。已有单题加3类按需请求保持最多4个原生生命期。Web页面关闭和系统杀进程不保证继续执行，重开只恢复记录，不自动重放付费请求；未开始照片点“继续待解题”，失败/取消任务点“重试未完成”。

不增加模型路由、题库或整卷批改，不重写 Pi loop，不增加依赖。批量自动核验增加费用，入口有说明。

## 验收

离线覆盖3并发上限、乱序完成、重复提交、取消隔离、停止队列、恢复不重放、历史题号及旧单题互斥。Web覆盖逐张加入、自动Verifier、题号顺序、分类搜索及整批删除。真实模型测试和原生构建结果另见 docs/BATCH_SOLVING_ACCEPTANCE.md；手机连续拍摄、息屏与系统保活须实机验收。

## 2026-09-21 排版与入口调整（0.1.40）

用户明确要求将批量选择放到打开相机之后。首页移除批量按钮和默认考试说明；相机底部切换“单题拍照 / 批量解题”，保存一张即后台入队，完成拍摄不自动打开答案页。每次打开相机的批量拍摄默认属于同一批；历史详情的“继续拍摄”追加到原批。批次默认名为本地日期、小时和编号，例如 `2026-09-21 14时 · 01`，同小时编号持久化递增；取消空拍摄可以留下编号空缺。

相机名称、批次详情名称及历史批次操作均可重命名，名称1～100字。单独的版本化 `batch-title.<id>` 文档只保存标题覆盖，读取记录、摘要和导出时合并；保存迟到模型结果时也沿用最新名称，不重写整批照片。删掉最后一张时删除覆盖标题，清空历史清理所有覆盖标题；保留单个 `batch-sequence` 编号文档。原记录的可选batch结构与旧导出仍兼容，不迁移或删除已有题图。

历史用一行等宽“单题记录 / 批量记录”标签加搜索图标，46px高度，切换用220ms下划线移动，跟随系统减少动态效果设置。搜索按需展开42px输入框，支持题号、关键词和批次名，不区分英文字母大小写；收起清除筛选，避免隐藏过滤条件。批次列表改为分隔线行，更多操作折叠；批次详情只保留返回、名称/张数和更多操作。并发限制、自动核验费用、后台行为等说明集中到“我的 → 使用说明”。不增加依赖，不改模型或Pi循环。

## 2026-09-23 完成拍摄后的当前批次（0.1.47）

用户明确要求完成批量拍摄后进入本次分组，修订 0.1.40 的“不自动打开答案页”行为。保存过题图的批次在相机关闭后通过既有导航成为当前题目，后台解题不停止；空拍摄关闭保留原界面。相机原生像素处理、校验原因可读展示和验证边界见 [0.1.47 记录](../BATCH_CAPTURE_0_1_47.md)。
