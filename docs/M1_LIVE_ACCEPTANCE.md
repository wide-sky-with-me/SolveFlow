## 费用预占与配置核实（2026-09-10）

保留既有累计 30 元账本及 19.368 元历史预占，不退款、不重置。新增每角色 `OUTPUT_BUDGET_MODE`，默认 `capacity` 保持原行为；明确配置 `request-limit` 才按请求输出上限预占。输入仍按完整上下文容量预占，包含图片；每次 Solver 外发前保留至少一次独立 Verifier 的额度。未知网关是否遵守总输出限制时必须使用 `capacity`。

本机配置型号的公开报价取自[当前供应商公开价格接口](https://www.dmxapi.cn/api/dmxapi/rmb/pricing/public)：`deepseek-flash-guan` 映射官方直连 DeepSeek-V4.1-Flash，容量 1,000,000 / 384,000。基础输入/输出为 1 / 4 元每百万 tokens，工作日两个高峰窗口翻倍，采用 2 / 8 的全天上界，缓存按更贵的普通输入预占。未执行远端计费表达式。

[上游 Chat Completions 协议](https://api-docs.deepseek.com/api/create-chat-completion/)定义 `max_tokens` 为生成 token 总上限，`completion_tokens` 包含推理 token；[网关参数说明](https://doc.dmxapi.cn/deepseek_think.html)明确提供 `thinking: {type: "disabled"}`。本机显式配置相应协议兼容项，锁定 Pi SDK 的实际请求测试证明发送 `max_tokens` 且思考关闭。按此供应商契约启用 `request-limit`，4096 输出目标对应每请求预占 `1,000,000×2/1,000,000 + 4096×8/1,000,000 = 2.032768` 元。这是基于供应商契约的保守估算，不是实际账单，也不是对所有兼容供应商的保证。30 元供应商硬额度继续生效。

模型、供应商、协议项及报价仍来自 `.env`，没有将这些具体值写进业务实现。更换供应商或模型时须重新核实该模式。供应商实际账单核对需要管理接口凭据，目前只有模型调用凭据；不索取额外管理权限，也不把估算当作已核销费用。
