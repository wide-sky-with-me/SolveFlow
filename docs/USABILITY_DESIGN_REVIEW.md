# 拍照解题到展示：功能与可用性审查

2026-09-14实施进展：本评审为改动前基线；澄清/追问连续性、题干更正、上传前裁切、原图放大和部分展示改进已落地，具体范围及未完成项见 [可用性增量验收](USABILITY_ACCEPTANCE.md)。
日期：2026-09-14。依据当前源码、既有验收记录及竞品官方公开说明。本文是设计建议，未修改应用、启动服务或发起真实模型调用；没有实测竞品App，也无法据公开宣传确认其内部Agent/OCR/检索架构。优先级表示本次建议，不替代已有实施授权和安全门槛。

## 结论

本地最小链路已经接通，私有上传、独立校验、SSE恢复、结构化公式/图示、多题分组有实现与验收。当前更明显的缺口是：识错后难纠正、澄清/追问缺少精确上下文、单题与多题展示不统一、复杂内容被有限图形和步骤协议约束。建议先完善这些闭环，再增加新的Agent能力。

Agent可以动态选择方法，但学生需要确定的交互：正在解哪道题、题干是否读对、为什么这样做、哪里不确定、出错后怎么继续。模型的自由度应落在解题方法与工具选择上；题目归属、证据、资源权限、校验和展示顺序需要明确协议。

- [作业帮官方页面](https://zyb.zybang.com/?fr=zyb_sem_sm_jm_01)展示搜索答疑、详细解析和视频讲解。可以借鉴讲解层次，但本阶段无需复制题库、直播课程、付费体系或整卷批改。
- [Photomath官方帮助](https://support.google.com/photomath/answer/14333327?hl=en)明确支持调整扫描框、手动输入和编辑扫描后的题目；[官网](https://www.photomath.com/)说明分步学习和可能的多种解法。最直接的启发是识题纠错入口、步骤展开和按需换一种解法。

上述是公开产品行为。传统题库命中路径与按题生成、再独立验证的路径不同，不能直接承诺同样的“秒出”体验。

## 输入与澄清的具体设计

建议流程：拍照/相册 → 原图预览并可圈选 → 确定所选题与识别条件 → 解题/校验 → 分题展示 → 针对某一步继续问。

不是每次都加“请确认识别结果”的拦截弹窗。清晰题直接继续，识别题干可随时展开检查；缺失关键数字/选项时才局部澄清，题图区域高亮。提示不依赖模型自报未经校准的置信百分比。

题目对象应连接：受授权image/region、原始题号和小问、识别文本、选项、图形标记、已知/待求/不确定项、用户修改版本。用户改题干产生新版本，Verifier看原图、修正说明和当前版本；旧版PASS不能自动沿用。

支持“补拍这块区域”需要上传绑定和来源关系，不能把用户给出的图片URL当授权。先做同一张图的局部选择与文字更正，再评审多图补充。

## Skill与工具如何增强Agent的适应性

当前通用Skill、代数Skill和图示Skill是一个起点；真实入口没有启用全部规划中的学科/MCP/SymPy能力。建议优先增加方法层，而非按科目堆同样模板：

| 方向 | 应约束的判断 | 配套能力/验证 |
| --- | --- | --- |
| 题目理解 | 条件、选项、小问、图文对应与歧义；不要猜图形比例 | 区域阅读、用户更正、转录与原图一致性 |
| 教学讲解 | 先给方法依据，再给关键推导；根据题目难度调整粒度 | 可选学段/已学方法、学生指定的困难步骤 |
| 数学推导 | 等价变形、定义域、单位、近似与回代 | 数值计算；符号工具仅在隔离验收后注册 |
| 几何与图表 | 依据显式条件建图，区分示意与严格比例 | 标注角/平行/垂直、阴影、受力箭头、表格数据与坐标 |
| 材料题 | 将结论关联原文证据，区别概念解释、事实和观点 | 段落/句子引用、材料高亮；外部事实必要时走已配置证据工具 |
| 失败恢复 | 看不清、缺条件、能力不可用、格式错误分别处理 | 有界澄清/格式修复和明确学生可执行动作 |

安全政策、所有权和输出协议应留在系统/服务端，不能由Skill决定。保留Pi原生按描述发现、按需read；同一run复用已读方法，避免每题重复读。缓存仍须遵守身份、撤销和预算计数。

工具优先级建议：

1. **看清题目**：授权局部图读取/缩放，返回原图坐标和来源；纯像素放大不能恢复已丢失细节。
2. **核对计算**：保留受限calculate，按真实题型补单位/精度检查；隔离数学服务完成验收后再支持符号求解。
3. **准确表达**：受审图形描述、题图标注与可核验引用；先建结构再渲染。
4. **外部信息**：仅在必要且已配置时搜索，不能让一般代数题为“显得像Agent”额外搜索。

首阶段不需要任意Python或前端代码生成；也不需要为每道题启动多个自主Agent。现有Pi循环、业务状态机、独立Verifier足以承载这些改进。

## 展示模式与结果协议

保留现有Markdown/KaTeX/安全图形渲染，无需重换整套前端。可渐进引入有界、声明式内容块，让正文、公式、表格、引用、图示和提示交错出现；模型决定需要何种内容，前端决定安全布局。

建议题卡包含：题号/小问与原图局部、识别题干、可选“先给提示/完整解答”、方法摘要、教学步骤、结论、校验说明、逐题/逐步追问。选择题显示选项正文和字母；证明题强调论证，阅读题关联原文依据，不能一律强制按计算题形式写2–4步。

“逐步展开”同时包含两层：解答逻辑有层次；界面允许只展开需要的部分。先做折叠/展开、题目导航、原图与讲解联动和“为什么这一步”，不自动生成多个解法增加延迟。换解法由用户按需触发。

图形的数学正确与显示正确是两项验收。除坐标真值外，还应检查文字遮挡/越界、图例、单位、局部放大和320px阅读；化学命令等现有KaTeX未必支持的语法，须先做真实表达能力样例再决定插件。

统一题目表示属于协议演进：新增字段/结构版本、旧结果兼容和旧页面刷新策略必须设计。已有v1分组是过渡方案，本轮不改历史答案或暗中升级状态机。

## 等待、失败与恢复

现有安全SSE与断线恢复应保留，不为缩短体感延迟向学生流出未校验正文或内部思维链。先增加真实的逐题阶段、已等待时间和“可离开，任务继续”的说明，不展示伪造百分比/预计秒数。工具事件当前在phase结果返回后汇总，前端也未映射成学生可理解的即时进度；要改善需真正打通事件时序。

4题真实历史样本为67.474秒；这只是一个样本，不是P50/P95。排队计入120秒，当前workerLoop串行领取执行，负载增加可能在真正解题前消耗预算；并发和队列等待时间需单独测量，不直接放大并发。

格式问题已经在真实记录出现：JSON_INVALID有一次语法修复；SCHEMA_INVALID仍直接失败。建议对空可选字段等纯格式问题定义白名单规范化/有界修复，仍严格验证最终schema，不推测数学内容、不生成缺失证据，也不修补权限/题目归属违规。不要把这类错误统一提示为“请重新拍照”。

未验证历史答案要保留状态，不能只截取裸结论再送回模型当可信事实。追问失败、取消或新模型不可用时，仍显示最后一次有效解答；重新求解创建版本且明确校验状态。

## 建议实施顺序与验收

| 批次 | 交付 | 可验收场景 |
| --- | --- | --- |
| A：恢复可用闭环 | 原解答常驻；澄清与题/步上下文；错误动作和限流原因 | 追问失败后旧答案仍可读；回复“是3”可补齐上一轮指定字段；达到会话上限不会被误导反复等待 |
| B：拍得清、选得准 | 裁切/题目选择、原图缩放、题干编辑；HEIC处理策略 | 四题中选第2题；更正一个负号生成新版本；模糊区域能定位补充；iPhone/Android实机测试 |
| C：讲得懂、图对题 | 统一题卡、图文交错、逐步追问、可选学段/讲解模式 | 第2题第3步追问不串题；图示位置正确且标注可读；阅读/几何/证明不被迫套代数模板 |
| D：更灵活的能力 | 逐题结果/重试、所需Skill与受审工具、更多可验证图形 | 一题澄清不丢其他已通过答案；声明过的每种图形与工具都有对应输入/失败/渲染样例 |

A可利用已有组件/协议作较小改动；B/C涉及已知M2项及结果协议扩展，D涉及状态/预算设计，实施时需按AGENTS同步技术方案与ADR。候选按题发布依然要求该题独立验证，不能把一个整组PASS随意拆成多个保证。

移动适配不能只以“无横向溢出”验收。还需真实手机拍照/相册、慢网上传、锁屏恢复、键盘遮挡、长题阅读和识图纠错。当前开发入口绑定127.0.0.1，设备模拟不等于手机实机可访问；受控HTTPS测试入口是实机验收前置项，不在本次审查中自行开放公网。

建议新增观测指标（先采基线，再定目标）：上传到首次有效反馈、按题首个已验证结果/整组完成时延、澄清后成功率、纠错成功率、错误动作后恢复率、逐步追问解决率、不同题型/图片质量下的正确率和误拒率。不得以软件测试数量替代这些产品指标；题干/学生对话仍不写入普通日志。
