# 题目字体与公式基线（2026-09-21）

用户反馈题面文字与公式字体不一致，并且行内符号与文字略微错位。本次只调整展示，不改题目内容、模型提示词或存储。

## 原因与修改

旧正文使用系统无衬线字体，手机主题可能进一步替换成个性字体；KaTeX使用随包数学字体，并默认按正文的1.21倍显示。行内公式原为`inline-block + overflow-x:auto + vertical-align:middle`，按整块中线对齐，无法保持与正文相同的文字基线。

在`apps/mobile/src/dom/answer.css`统一调整：

- 题干、选项、答案、步骤、追问、更正预览及历史摘要的Markdown正文，复用已打包的KaTeX_Main文本字体；中文使用随包Noto Serif SC，内部CSS别名SolveFlowReadingCJK。界面导航和按钮不改用数学字体。
- 公式基础字号改为1em，保留KaTeX内部的数学斜体、符号字库、分数、上下标与伸缩括号尺寸规则，不强制全部子节点继承普通正文字体。
- 行内容器改为inline-flex并沿基线对齐，内部公式不收缩；保留超长公式横向滚动，不用固定像素偏移，也不裁掉上下标。

0.1.42将用户“字体统一”的要求实现为固定阅读字体，因此增加随包Noto Serif SC Regular资源，不增加运行时依赖。101个官方WOFF2分片共3,180,564字节，在`apps/mobile/public/fonts/noto-serif-sc-v35/`只保存一份，Web和本地DOM页面按字符范围使用；未把中文二进制重复内嵌到三个文档。仅无字库覆盖的罕见字符才由系统兜底，常用中英文正文不依赖设备主题。导航和应用外围原生控件仍遵循原界面字体。

来源为[Google Fonts官方Noto Serif SC](https://github.com/google/fonts/tree/main/ofl/notoserifsc)及其v35字体分片，使用[SIL OFL 1.1](https://github.com/google/fonts/blob/main/ofl/notoserifsc/OFL.txt)。原WOFF2文件未修改，来源URL、大小和SHA-256逐一保存在manifest.json，完整许可随包保留。下载仅发生于开发准备，应用运行时只读取本机资源，不访问Google Fonts。字体上游内部名称为`Noto Serif SC ExtraLight`，实际CSS请求使用400字重；测试以其真实名称核验，不能误认为发生了字体回退。

## 验证

新增`tests/mobile-e2e/reading-typography.spec.ts`，使用合成题同时展示正文数字与公式数字，测量实际字符范围的高度和基线；通过浏览器字体接口确认正文实际使用随包字体。另检查根号、分数、上下标、希腊字母、求和、长行内公式、浅深色及历史摘要。

旧0.1.41实际APK资源输入同一测量样本：正文16px、公式19.36px，基线差2.765625px，新增断言失败。新版桌面/手机浏览器：两者均16px，样本字高差和基线差均0px。这是同字形样本的浏览器测量，不表示所有数学构造具有相同外接框或所有手机像素都完全一致。

相关Playwright桌面/手机14项通过：新排版、选择题ABCD/FGHJ、公式/表格/图像、安全渲染、历史管理和降级、澄清及追问。lint、根/mobile严格类型检查、三端Expo导出与资源检查通过。本轮为CSS排版变更，没有重跑后端整套单元或数据库集成测试，也没有真实模型请求。

合成题截图、字形测量及手机截图仅保存在忽略目录`.runtime/typography-review/`。


最终固定字体复测覆盖模拟cursive系统个性字体，浏览器实际字体接口确认中文和拉丁字母全部来自自带字库。APK内101份字体的SHA-256与清单逐一匹配，只有一套WOFF2文件，压缩后共3,181,809字节；最终APK为23,858,088字节，比0.1.41增加3,336,020字节。APK本地DOM测量正文/公式均16px、数字样本基线差0px，中文实际使用自带字体；无在线字体请求，资源、安全与桥接检查通过。

## 0.1.43 跟随手机字体（取代上面的固定正文方案）

用户明确希望自动使用手机默认/个性字体。0.1.42仅固定了正文，外围控件仍是系统字体，导致混用。现删除正文和选项标签的固定font-family、字体注入模块及101个Noto字体资源，所有普通阅读文字继承文档系统字体，与标题/按钮一致；原生控件继续使用设备默认字体，不读取或复制手机字体文件，不新增权限或依赖。

KaTeX内部数学字体保留：其中数学斜体、伸缩括号、根号和分数依赖专用字形与排版尺寸。强制改为任意个性字体会影响位置与可读性；并非承诺所有公式也具有手机字体的外观。仍保留1em基础字号、inline-flex基线与长公式滚动。浏览器原生MathML方案本次未采用：不同浏览器的数学字体/变体支持需要独立验证，不能为了外观改变特殊数学记号的含义。

新增系统字体继承断言在旧版首先失败（期望cursive，实际KaTeX_Main/SolveFlowReadingCJK）；修改后相关14项桌面/手机Playwright通过，覆盖个性字体模拟、实际系统字体来源、公式基线探针、字号、分数/上下标、320px浅深色、历史、选择题与追问。不同字体的字形外接框不等同于排版基线，因此保留外接框测量作诊断，以零高行内基线探针验证真正的基线。lint、根/mobile类型检查与三端Expo导出通过。本轮不改数据或模型，未重跑后端全套测试、未调用付费模型。最终APK本地DOM资源测试通过：正文/公式均16px，数字字形外接框底部相差1px，真正的排版基线探针差0px；旧固定中文资源已不存在，三份DOM桥接、离线资源与安全检查通过。安卓0.1.43 / versionCode44为20,522,084字节，比0.1.42减少3,336,004字节，SHA-256 `801a67ac3c0c3ce42a0f9283f12dde144cb0d65bdde678012125ce723ffc3aaf`，签名与旧版一致、私密配置扫描通过。
