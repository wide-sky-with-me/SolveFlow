# 0.1.46 批量相机稳定性修复（2026-09-23）

用户报告连拍及静置时均有跳动，本轮分别处理界面重排和持续自动对焦。沿用现有手机、模型及付费测试授权；不改模型配置。

## 复现与修改

- 0.1.44 真机连拍录像显示快门文字从“拍摄”变为“拍摄中…”后，底部按钮换行，预览高度改变。新增浏览器回归在 360×800 下复现预览缩小 58 px。`camera.tsx` 固定按钮文字，将忙碌状态放在现有预览提示位置，避免拍摄状态改变几何布局。
- 静置时设备使用 `CONTINUOUS_PICTURE`。采样报告焦距变化，符合反复寻焦的表现；录像前段存在手持移动，不能将全部位移都归因于对焦。
- `camera-preview.native.tsx` 对安卓批量模式采用一次对焦后保持，点击预览释放并重新对焦；单题仍持续自动对焦。切换镜头、退出相机和模式切换会释放本地重对焦计时器，拍摄中不接受重复对焦操作。
- 焦点取画面中心，不是点击位置。移动到下一题或改变距离后，将题目置于中央再点击预览。该操作说明同时加入使用说明。
- 锁定版本 `expo-camera@57.0.5` 的 Android 实现需要补丁：绑定相机后应用已选对焦模式、测光点从像素坐标 `(1,1)` 改为预览中心、关闭 CameraX 默认定时取消。补丁位于 `patches/expo-camera@57.0.5.patch`，通过 pnpm `patchedDependencies` 和锁文件管理，没有升级依赖。`apps/mobile/package.json` 为 Android 指定 `expo.autolinking.android.buildFromSource: ["expo-camera"]`，确保使用修改后的源码，而不是 Expo 默认的预编译 AAR。源码编译还暴露了关闭扫码时的可选 ML Kit 类缺失：原库把这些依赖设为 `compileOnly`，但没有相应的消费者规则。补丁只在 `barcodeScannerEnabled=false` 时为明确列出的扫码类加入 `dontwarn`；相关入口已有 `CameraUtils.isMLKitBarcodeScannerAvailable()` / `isMLKitAvailable()` 保护，其余缺失类仍报错，未引入 ML Kit 体积或启用扫码。升级相机库时必须重审补丁、可选依赖保护及真机对焦行为。
