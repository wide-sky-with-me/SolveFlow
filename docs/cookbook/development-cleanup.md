# 开发产物清理

从仓库根目录执行。清理只针对已确认不用的开发产物；先读[本地Web指南](local-web.md)，区分服务、题目数据与构建目录。不要对`.runtime/`整目录删除，也不要用`git clean -fdx`代替分类。

## 盘点与保护

1. 用`git status --short`识别已有改动。未提交源码、测试、规则、决策和报告都不是临时垃圾；本轮清理前保存修改清单或源码快照。
2. 读取本次服务的PID/URL元数据，核对进程命令、仓库目录和实际构建根。PID会复用，不能仅因同号进程存在就认定是旧测试服务。
3. 对`.runtime/`按目录统计体积，先列候选清单。不要输出`.env`、配置密钥、题图、模型原文或整个进程环境。
4. 保护正在服务的`dist`及其旧哈希资源：已打开页面可能延迟加载旧资源。依赖dist、生成的移动资源与原生工程均先核对使用方。

## 处理规则

| 内容 | 操作 |
| --- | --- |
| 已停止测试服务的Expo导出 | 核对目录仅含生成的入口、资源、字体与元数据后可删除；记录目录、字节数和入口哈希，保留原日志与源码快照 |
| 当前服务、配置、生效预设、签名及SSH材料 | 保留；不因位于忽略目录就清除 |
| 真实题图、识别/付费复测结果、用户浏览器快照、备份与导出成品 | 默认保留，不能当作可重建缓存 |
| SDK、Gradle及pnpm缓存/存储 | 按源码配置核对；本项目的依赖存储也在`.runtime/`，删除可能影响后续离线构建，不作默认清理对象 |
| 失败截图、日志、结果JSON、修改前源码 | 保留可追溯证据；报告不因临时构建被清理而改写旧成绩 |
| 冻结文档及历史决策 | 沿[历史资料政策](../archive/README.md)，不删除、不刷新哈希绕过保护 |

## 验证与交付

删除前再次核对候选路径和摘要，拒绝外部路径、符号链接、活动目录及盘点后发生变化的内容。只移除具体候选，不顺便清空父目录。

清理后确认用户服务仍在原PID和目录运行，首页及所引用静态资源可以读取；只查静态文件，不触发真实模型调用。代码整理另按影响范围执行类型、回归和构建检查；文档改动运行`pnpm docs:check`。记录实际移除量、保留范围及验证结果，避免把保留依赖缓存后的目录体积误报为清理失败。
