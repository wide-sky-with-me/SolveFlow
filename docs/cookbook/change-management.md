# 一次变更的管理步骤

1. 从根规则和目标目录规则进入，确认源码与当前文档；用 `rg --hidden -n '关键词' .agents/notes docs/adr` 查相关原因，不全量注入历史文档。
2. 明确行为、失败场景和验证范围。查看附近的 `Decision: .agents/notes/...` 注释，避免再次采用已被实测否定的方案。
3. 修改契约、实现和相关测试。当前行为变了，更新唯一所属的 `subsystems/` 页面；可复用操作更新本目录的指南。归属、格式与引用按 [编写约定](documentation.md)。
4. 若涉及架构选择、持久化兼容、安全/权限、并发/生命周期或有证据的性能取舍，先查已有笔记。尚未实施的提案放 `proposed/`，实际完成后才进入 `implemented/`；小样式和机械改动免写。
5. 使用 [笔记规则与模板](../../.agents/notes/README.md)。真实考虑过的方案才写入“放弃的方案”，未知原因明确未知，不补造历史。验证写实际命令/结果和未验证项。
6. 按 [笔记生命周期](../../.agents/notes/README.md#查找与生命周期)处理完整或局部替代，包括归档冻结登记；归档原文和旧测试成绩不重写。
7. 关键机制的源码用一行仓库相对 `Decision:` 路径关联笔记，笔记反链源码。不要到处加重复注释或维护全局 `INDEX.md`。
8. 执行相关验证及 `pnpm docs:check`；检查器自身变更运行 `pnpm docs:test`。最终记录结果、限制、产物和后续步骤，未经授权不提交/推送/部署。

## 检查范围

[策略文件](../../scripts/docs-policy.json) 定义当前文档路径、长度与原路径冻结档案。检查器检查归属、正文长度、本地文件/标题链接、笔记必填章节及第三行日期/状态与路径的一致性、源码决策引用与冻结内容；不连接外网验证 URL，也不判断自然语言是否正确。

`scanRoots` 递归检查既有 JS/TS、Kotlin、Python 及 YAML 源文件中的 `Decision:` 注释；仓库根的单独配置通过 `sourceFiles` 显式登记，目前包括 `pnpm-workspace.yaml`。同一路径只计一次，目标必须是已实施笔记且反链该文件。检查器不遍历用户目录、秘密配置或生成产物，不执行被检查文件。

当前文档使用 `#` 风格标题；链接支持 Markdown 行内、引用式及尖括号路径，忽略行内代码和代码围栏中的示例。标题片段按 GitHub 常用 ID 形式检查；复杂 HTML、自动生成导航和完整 Markdown 解析不在覆盖范围。

长度使用“每个 CJK 字符 + 其他词”的计数单位，兼顾中文，不称作模型 token。超限先搬到正确层级或精简；必要的上限变更随决策评审。不要以新增冻结条目或改哈希绕过新文档检查。

历史资料迁移不自动修正当时的错误或改变授权。要更正某项结论，写新证据和适用范围，并更新当前文档链接。
