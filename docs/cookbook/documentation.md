# 文档编写约定

用于维护仓库开发文档，帮助开发者和 AI 按任务找到可靠信息。先按下表确定归属，再编辑已有页面；变更与验收流程见 [变更流程](change-management.md)，学生提示不适用本约定。

## 内容归属

| 内容 | 维护位置 | 写作重点 |
| --- | --- | --- |
| 项目介绍与快速启动 | [根 README](../../README.md) | 产品用途、运行入口，不展开实现 |
| 当前系统地图 | [架构](../architecture.md) | 模块、依赖方向和产品边界 |
| 运行语义与失败处理 | `docs/subsystems/<topic>.md` | 责任、状态、顺序、限制及源码入口 |
| 可复用操作 | `docs/cookbook/<task>.md` | 前提、步骤、成功/失败判断和清理 |
| 已验证范围与待办 | [发布状态](../project-status.md) | 注明核对日期，链接证据及完成条件 |
| 某次事故或集中验收 | `docs/postmortem/YYYY-MM-DD-<topic>.md` | 当时范围、实际结果、失败与未验证项 |
| 开发约束 | 作用目录的 `AGENTS.md` | 简短、可执行；操作细节链接指南 |
| 长期取舍 | [决策笔记](../../.agents/notes/README.md) | 沿用既有模板，不另建全局索引 |

同一事实只在所属页面解释，其余页面链接到该位置。协议字段以 [共享契约](../../packages/contracts/src) 为准，容量/超时限制沿所属实现核对，工具版本/命令以 [根清单](../../package.json) 为准，依赖解析以 [锁文件](../../pnpm-lock.yaml) 为准，应用版本以 [应用配置](../../apps/mobile/app.config.ts) 为准。报告中的版本和数值是当时证据，保留原值。

## 文件与排版

- 新主题文件使用小写英文短横线命名；`README.md`、`AGENTS.md` 和已有 PR 模板沿用约定名称。日期使用完整 `YYYY-MM-DD`；跨日范围两端都写完整日期，报告文件名取开始日期。
- 正文文档只有一个 `#` 标题，按 `##`、`###` 连续分级；PR 模板沿用已有结构。标题概括内容，避免只写“优化”“其他”。标题、段落、列表和表格之间留空行。
- 正文默认中文，代码符号、命令、路径与状态枚举用行内代码保留原名。时间/容量写明单位，如 `21 ms`、`128 MiB`；命令、哈希和日志原文不做排版替换。
- 代码块标明语言；完整可运行命令写明工作目录和前提，占位命令说明要替换的值。不从报告直接复制旧环境、设备标识或已结束服务地址作为操作步骤。
- 仓库引用使用相对 Markdown 链接，锚点对应现有标题；改标题时搜索引用。源码目录可链接，暂存证据用行内路径并注明保存范围，不依赖未提交日志才能读懂结论。

## 表述与证据

开头说明适用范围。子系统按责任、行为与失败边界组织；操作指南按前提、步骤、验收与清理组织；验收报告沿用 [报告模板](../postmortem/README.md#报告模板)。小文档可合并相邻内容，不为填满模板添加空章节。

使用完整对象名，避免“第三项”“上面的方案”等依赖聊天的表述。报告明确日期、版本和环境，“本次”只指该报告范围；时效性结论加核对日期。区分已实现、已执行通过、失败、未验证及待办，历史复测不改写原始成绩。

新证据更新发布状态及对应报告链接，不把每次测试结果写进架构。格式整理可以调整未冻结报告的标题与导航，但不能删除失败、改动样本/指标或把后来的验证算入原成绩。冻结文件按 [历史资料政策](../archive/README.md) 保留。

## 检查

运行 `pnpm docs:check` 校验归属、长度、本地链接、笔记日期/状态、决策引用和冻结哈希，扫描范围见 [变更流程](change-management.md#检查范围)。上述编写约定还需人工检查；该命令不校验所有排版、报告完整性、外链可用性或事实正确性。修改检查器时另运行 `pnpm docs:test`；纯文档整理无需应用构建。
