## 规则

- 单位为整数micro-RMB（1元=1,000,000单位），每个显式授权预算窗口累计预占最多30,000,000单位；quoteMicros用BigInt按token上限和受审报价向上取整，并可计入固定费用。
- 每次外部调用必须先reserve并等fsync成功，再dispatch。重复attempt ID不允许再次执行。Solver、Verifier、失败、超时、修正和任何重试都必须使用独立attempt ID并预占。
- 采用保守不退款：settle记录已确认费用，但不释放原预占额度；未知账单保持全部预占。不是把预占当作实际已扣费。
- 实际账单超过预占立即禁用实例，关闭后保留锁，必须人工核对。写入失败同样禁用并保留锁。不得在捕获异常后继续调用模型。
- 启动重放全部记录；重复、越限、未知字段、不匹配结算或半行记录均失败关闭。账本最多1MiB，满后停止，不自动轮转丢失累计数。

## 运维前提与限制

- 路径及祖先必须由管理员控制，不能有不可信进程并发修改。最终文件拒绝符号链接、硬链接和组/其他用户权限；文件应为0600。
- open只打开既有文件，**账本丢失时绝不自动创建空账本**。首次空账本须在真实调用启用前显式初始化，后续不得删除、换路径、清空或新建账本重置累计预算。首次初始化命令为 `pnpm probe:ledger:init`，永久 `.initialized` 标记阻止丢失账本后重新初始化。
- 使用O_EXCL锁文件拒绝第二个写者。崩溃遗留锁不会自动清理；需要确认原进程已结束，并与持久记录及供应商账单核对后人工恢复。不要仅按锁的时间或PID猜测可删除。
- 同步写入/fsync依赖本机文件系统保证，不承诺网络文件系统、宿主故障或恶意管理员篡改下的恢复。尚未做磁盘写失败/掉电故障注入。
- 账本只约束声明的保守费用，不证明供应商真实收费。报价必须覆盖上下文、图片、输出/推理tokens及所有额外收费；供应商侧累计硬额度仍然必需。不能用应用估算替代30元硬边界。
