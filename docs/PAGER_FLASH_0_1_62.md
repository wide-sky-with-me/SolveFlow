# 切题白帧修复（0.1.62）

2026-09-30，继续处理用户反馈的“切换题目还是会闪一下”。不修改模型、数据库结构或解题预算。

## 复现与修改

0.1.61 的真机录屏捕捉到第 49 题切向第 50 题时，旧题已滑走、新题正文尚未显示的白色画面。新增慢读取回归在旧 Web 导出上失败：目标题目仍在等 IndexedDB 返回，首题页面已被卸载。

- `question-pager.tsx` 区分等待、滑动、停稳。等待时保留原题与位置，目标就绪才滑入；每次过渡创建初始值为零的独立 `Animated.Value`，不再将上一轮进度先提交再归零。快速连点保留最新目的题，正在进行的读取和动画都不被后续点击中途重置，避免反复销毁冷加载页面而迟迟无法显示；返回当前停稳题则可取消尚未开始的滑动。
- 相邻预加载页面保持完整尺寸，放在当前不透明页面后方，不再移到屏幕三倍宽度之外；继续通过辅助功能隐藏和 `inert` 排除交互。仍保持每层稳定最多三页、过渡最多四页，不恢复全批 WebView 或图片缓存。
- `question-page-ready.tsx` 传递批量外层、单图多题内层及文档的就绪状态；`batch-question.tsx` 在记录读取完成后委托内层阅读器，`question-thread.tsx` 对原生进度/错误页直接就绪。
- `answer-panel.tsx` 等待 DOM 已提交、首次有效高度及后续两次布局帧，再报告可切入。仍不等待 `document.fonts.ready`。用户请求的后台目标页启用原有前台十秒文档期限，即使首次测量缺失也会显示文字回退，不会一直停在旧题；非请求预加载页不消耗该期限。

## 真机复查

本次设备读回 Android 16（上一轮记录写作 Android 15，以设备实际查询为准）。覆盖安装后六个批次仍可见，题数为 50、1、22、22、27、27。仅浏览已有结果，不调用真实模型，不清空数据。

首次修复包的同一 49/50 题之间六次切换录屏中，滑入页面已带正文，未再观察到旧版的空白正文帧。对两段 630×1400 录屏逐解码帧检查正文区域（x=25…604，y=450…1219），以灰度小于 160 的像素占比低于 0.5% 筛选近空白帧：旧版 210 帧中有 6 帧命中（含占比为零的白帧），新版 262 帧中 0 帧命中，最低占比 5.78%。已查看两段最低占比帧，分别为空白正文、两页正文滑动接合。此检测仅针对这组长文本题的明显白帧，不等同通用图像判定、稳定帧率或所有设备保证。切换后为 3 个 WebView、TOTAL PSS 391,822 KiB。

最终包另外从首题快速点击下一题 18 次（每次间隔约 0.3 秒加 ADB 命令耗时），最终到达 19/50。录屏显示内容持续推进，不再因连点反复重建冷加载页而长时间停在同一题；快速请求可合并中间目的题，最终目的题准确。482 个解码帧在同一正文区域筛查中，近空白命中 0 帧，最低深色像素占比 3.36%，已查看最低占比帧为正常题目滑入。切换后系统报告 4 个 WebView（分页限制为每层窗口，内层多题及系统对象计数不等于外层页数），TOTAL PSS 412,127 KiB，静置后 294,252 KiB。

该段录屏期间 `gfxinfo` 为 419 帧、Janky 79（18.85%）、中位 7ms、p90 34ms、p95 46ms、p99 53ms。**仍存在快速冷切掉帧，不能称零卡顿。** 录屏、题目序列和加载状态影响样本，未将这些数据当作与旧版严格同条件的帧率对比。

本次没有修改服务端持久化或私有对象存储，未重跑相关数据库集成测试；未构建已暂停的原生 iOS。手机录屏仅保存在忽略目录 `.runtime/`，不提交真实题图。
