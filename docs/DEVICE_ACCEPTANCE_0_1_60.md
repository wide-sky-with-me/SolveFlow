## 1. 深度病因定位（为什么上一版依然会“闪一下”）

在 v0.1.59 中，虽然解决了 React `useEffect` 的 1 帧延迟与 Android `display: 'none'` 销毁 GPU 纹理的问题，但在实际设备运行高刷（120Hz）环境下，用户切换题目时仍然会感知到轻微“闪一下”。

经对渲染树与 Yoga 布局的逐帧审查，定位到了以下核心根因：

1. **绝对定位与 Flex 相对定位动态切换引起的 53px 垂直位移跳变**：
   - 在 `QuestionPager` 原结构中，题号导航栏 `styles.navigation`（高约 53px）与题目页面组件是直接并列的兄弟节点。
   - 在静止状态下，当前激活页使用的是 `{ flex: 1 }`（相对于导航栏下方排列，其 `top` 坐标为 53px）。
   - 一旦用户点击切换，激活页为了参与水平滑动被切换成了 `StyleSheet.absoluteFill`（相对于整屏根容器 `styles.root`，其 `top` 坐标瞬间跳到了 0px，直接伸入导航栏背后）。
   - 在 240ms 滑动结束后，新激活页又从 `StyleSheet.absoluteFill` 瞬间切回 `{ flex: 1 }`（`top` 坐标瞬间从 0px 掉回 53px）。
   - **结果**：在开始切换的瞬时页面向上跳动 53px，在滑动结束的瞬时页面向下落回 53px。这种垂直位置突变在高刷屏幕上呈现为明显的“闪动/抖动”。
2. **首次切换未访问题目的 WebView 冷加载白块**：
   - 切换到尚未加载过的题目时，WebView 首次挂载、HTML 初始化及 KaTeX 布局需要耗费约几十毫秒，此时未预热页面会导致短暂白屏或高度重排。
3. **数据读取的异步微小间隔**：
   - `BatchWorkspace` 原先在进入批次时异步并发读取 `batchRecordCache`，如果切题速度快于缓存写入，偶发触发 1 帧的“正在读取题目…”占位符。

## 2. 彻底解决措施 (v0.1.60)

### 2.1 引入舞台层 `styles.stage`，实现永久绝对定位（零垂直位移）
- 将所有滑动页面包裹在专门的舞台容器 `<View style={styles.stage}>` 中，舞台容器自身在导航栏下方通过 Flex 布局固定，占据全部剩余高度与宽度。
- 舞台内的所有页面（激活页、滑出页、保留的后台页）**永久使用** `position: 'absolute', top: 0, left: 0, right: 0, bottom: 0`。
- 页面在静止和动画切换期间，**其定位模式永远不变、垂直位置永远为 0、高度永远为 100%**。
- 动画只作用于水平 `translateX`。动画结束时，仅移除已归零的偏移，没有任何视图模式切换，彻底消除了 53px 的垂直抖动。

### 2.2 相邻题目后台静默预热 (Adjacent Pre-warming)
- 在 `QuestionPager` 中增加了闲置空闲预加载调度：
  - 当停留在第 N 题时，在 150ms 闲置延迟后，自动将第 N-1 题与第 N+1 题加入 `visited` 集合。
  - 相邻题目的页面在屏幕左侧外区（`-containerWidth * 3`）静默挂载，提前完成 WebView 解析、KaTeX 公式排版及 DOM 尺寸测量。
  - 用户点击上一题或下一题时，目标页面早已渲染就绪，直接执行 120 FPS 原生水平滑动，实现 0ms 视觉即时响应。

### 2.3 批量数据全量前置预热 (0ms 缓存命中)
- 在 `BatchWorkspace` 的 `refresh()` 中，在提交 `setRows` 之前通过 `Promise.all` 确保批次内所有题目的记录已经写入 `batchRecordCache`。
- 进入或切换任何题目时，`batchRecordCache.get(id)` 保证 100% 同步命中，杜绝任何中间状态闪现。

### 2.4 导航栏与占位背景主题无缝对齐
- 导航栏及加载容器背景颜色严格绑定 `themeColors[scheme].background`，彻底消除黑白切换色块。
