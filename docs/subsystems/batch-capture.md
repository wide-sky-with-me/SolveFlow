# 批量连续拍摄

[拍摄流程](../../apps/mobile/src/components/batch-capture.tsx)在批量模式把照片加入同一批次；[相册导入](batch-import.md)的顺序预览单独维护。

## 缓冲与顺序

快门完成取图后交给[有界缓冲](../../apps/mobile/src/batch-capture-buffer.ts)，无需等待归一化及保存便可拍下一张。缓冲最多持有3张待存照片，归一化可重叠；保存、位置递增和入队仍按拍摄顺序串行。沿用平台图片规范化、EXIF清理、尺寸检查及引擎容量终检。

“已保存”仅包含持久化成功的题图，“待保存”单列。缓冲满或失败时禁用快门；待存期间暂停改名、切换模式、相册、调整及放弃整个批次。点击完成拍摄或正常返回会等待当前缓冲排空，再打开本批。拍摄缓冲不改变答题和校验并发。

## 错误与退出

归一化或保存失败保留本张及后续待存照片，暂停写入，提供“重试保存待存照片”及二次确认的“放弃未保存照片”。重试复用已有归一化结果；归一化失败才重新处理。放弃只释放待存照片，保留已保存题图。

保存成功而入队失败时，已保存计数仍递增；本张不会被缓冲重复入队。用户可以继续拍摄，回到批次后明确“继续待解题”。新任务仍服从[未保存结果阻塞](local-run-lifecycle.md)，不通过拍摄恢复绕过。

组件退出后已接受的写入可以完成，但不再入队或写后续照片。等归一化结束再释放原图及结果，避免删除解码中资源。Web有待存照片时注册浏览器关闭/刷新确认，排空后移除。缓冲是易失内存，强制刷新、杀进程或系统回收可能丢失待存项；已保存记录保持原持久化语义。设计原因见[决定](../../.agents/notes/implemented/storage/2026-10-25-continuous-capture-buffer.md)。
