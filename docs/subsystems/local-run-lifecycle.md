# 本地任务生命周期

入口为 [LocalEngine](../../packages/client/src/local-engine.ts)。说明顺序与并发；存储格式、备份与失败结果归 [存储文档](storage.md)，模型核验规则归 [解题核心](agent.md)。引擎编排设备业务，Pi拥有模型/工具循环。

## 先分清标识

| 名称 | 含义 |
| --- | --- |
| sessionId | 一张主图、同题补充材料及其会话，主图可能包含多个明确题号 |
| runId | 一次请求；重新解题另建 run |
| sourceRunId | 按需内容或追问所依赖的已保存答案版本 |
| context.number | 图内题号；不是批量拍摄序号，也不是 run 序号 |
| seq | 单个 run 的公开更新序号；不能用设备时钟推断提交顺序 |

字段以[任务契约](../../packages/contracts/src/http.ts)为准。

## 提交与执行

1. `start()` 拒绝正在删除或调整范围内题目的新提交，全库清空才阻止所有题目；其他批次继续准入。在引擎锁内读取题目并检查并发槽位，此锁串行化准备和最终写入，不包住整次模型执行。
2. [prepareLocalRunRequest](../../packages/client/src/local-run-request.ts) 校验消息/上下文、次数、同题重复和已缓存内容，从已保存答案解析校验目标，再构造限定题目的历史并解码原图与本次材料。此阶段不写库、不占槽、不调用模型；失败不能留下 queued。
3. 创建并保存包含材料 ID 快照的 queued run，成功后占用对应槽位、发布进度，启动后台保护。`start()` 返回已接受任务；完成等待由 `waitForRun()` / `waitForIdle()` 提供。
4. 模型在锁外执行。进度必须属于本 run，取消或终态后的进度忽略。诊断有界，异步写入串行处理；后台启动失败不派发模型。
5. 有效候选在锁内重新读取、保存未验证pending检查点，再发布verifying进度，答案即可查看。批量保存候选后释放solver位，独立FIFO等待核验位，不占答题槽。后台保护按[平台生命周期](device-runtime.md#平台生命周期)持有或暂停。
6. 结果阶段等待诊断，重新拿锁读取最新会话，只合并本 run。不能用提交时的旧对象覆盖期间新增的其他 run。保存成功才发布终态，最后停止后台保护并释放槽位。

普通与辅助任务可并存，同题进行中限制追加会话；辅助重复键为种类、sourceRunId 和题号。批量池与新的普通会话互斥，已完成题目的辅助请求可与批量并存。步骤和知识列表要求源run终结，避免自动修正期间旧讲解关联到新答案；其他题目未完成不阻塞。上限见契约，原因见[学习准入](../../.agents/notes/implemented/architecture/2026-10-09-batch-learning-admission.md)。

批量求解与校验分别控制准入，共享设置中的执行并发；已经接受的解题及核验输入保持总量上限。尚未派发的队列仅保存题图ID和请求描述，多批次等待容量由设备契约单独限制。单批停止、启动失败和状态提示按批次隔离，存储保存故障仍全局停止派发；任务总览及导出边界见[批量任务](batch-tasks.md)。

批量重答与失败重试按本题活动/排队状态准入，复用有界队列和并发。空位派发，满额提示本题排队；不取消、重排其他题。失败重试与“重试未完成”保留原消息、上下文及备用选择，核对失败版本，已有答案不重放，同题去重；存储失败先保存已有结果。普通追问和更正的互斥不变。原因见[重试与阶段窗口决定](../../.agents/notes/implemented/architecture/2026-10-09-batch-retry-and-phase-time.md)。

## 材料与答案版本

普通解题、追问、重做用当前图片；旧记录无选择字段时用原图与全部补图。更正增删先留草稿，提交时图片、选择与queued任务共用事务，取消不写库。每个run的有序imageIds中首张为主图，其余为补图。步骤、知识点、校验的图片、更正与历史绑定源答案；旧run按原图及materialIds回读，后续增删/更正不改旧证据。辅助结果沿源链回到作答版本，按保存顺序限定历史，不用墙钟；普通追问/重做仍用当前条件。见[版本上下文决定](../../.agents/notes/implemented/agent/2026-10-20-auxiliary-answer-context.md)。补图重答见[流程](batch-materials.md)。

[学习上下文](../../packages/client/src/learning-history.ts) 为明确选中的源答案保留完整正文及分小问内容；同图多题先投影到指定题号，其他历史继续有界节选。用户长文上限由共享契约控制，不能无限扩大对话历史。写作点评作为源答案时，额外携带沿所引用版本链找到的同题完整作文（最多十层）到 focus.draft，供继续修订使用；没有原稿则省略，由模型明确请求补充，不从别题、同题其他分支或后续版本借用。标题、点评和化学反应结构与所选答案一同投影。

## 取消、保存和删除

`abort()` 固定第一次取消原因：用户取消产生 cancelled，期限到达产生失败及超时代码。取消不等于马上移除槽位，要等待任务和保存收尾。

存储事务进行中收到取消，首次写入未必能停止；引擎在发布前检查一次并补写取消结果。`committed` 保留首次成功写入的结果，使补写失败后的保存重试能识别该已知版本。不能删除这段“看似重复”的检查，也不能无限循环补写。

最终写入失败转入有界待保存集合，重试只落盘，不调用模型。重试若遇到不同且不属于已知首次写入的终态，拒绝覆盖。跨进程限制见存储文档。

删除先关闭目标题的新任务提交，排空已接受的准备，再取消相关运行并等待收尾，最后重新拿锁删除数据。其他题继续解题和派发，不把局部删除当作其启动失败；全库清空仍阻止全部新任务，新增题图、改材料及再次删除沿用操作互斥。等待 `active.done` 时不能持有引擎锁，因为结果保存也要获取它。只有删除成功才清除对应待保存结果；失败同样释放准入守卫。见[范围决定](../../.agents/notes/implemented/architecture/2026-10-29-supplement-scope-and-deletion-admission.md)。

批次调整先建立排序/移除草稿，取消不写入；确认后停止本批两条队列，等保存收尾，在一个存储事务中更新连续位置并删除被移除题目及其关联数据。保留题图原文和session答案，不重放模型。核对完整成员快照及重复/外来ID；成员变化、保存失败保留原批，未保存解答先处理。见[批次编辑决定](../../.agents/notes/implemented/storage/2026-10-10-scoped-history-and-batch-edit.md)。

“清空单题历史”只删除原记录确认无batch的题目，不影响批次。“删除本批”经确认只停止并删除指定批次，事务成功后才清除内存结果。未知归属的损坏记录与孤立诊断保留给维护，不执行全库删除。无多记录事务时拒绝执行。

## 修改时一起读

[引擎回归](../../packages/client/src/local-engine.test.ts) 覆盖排队失败、缓存、并发、图片校验及保存中取消；[存储故障](../../packages/client/src/storage-recovery.test.ts) 覆盖补写失败后重试；[历史回归](../../packages/client/src/local-history.test.ts) 覆盖删除与已接受准备的竞态。正常解题不足以验证这些边界。

主动校验判错且已启用备用时，由本轮内存续接创建一版重新解答，旧答案和失败校验均保留；派发前在准备锁内核对原校验终态、最新答案版本及续接代次。取消、删除、新任务、补图或配置变更撤销尚未派发的续接；启动、重载与保存重试不会恢复它。已派发的新解答沿通常取消和持久化路径执行。见[直接核对决策](../../.agents/notes/implemented/agent/2026-10-09-direct-answer-review.md)。
