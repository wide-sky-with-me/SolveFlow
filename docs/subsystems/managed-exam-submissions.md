# 题图提交与断线恢复

适用中心考试的首拍、重拍和补图；题位、版本与任务规则归[中心平台](managed-exams.md)，临时拍题另行维护。

[学生草稿](../../apps/exam-web/src/browser/student.tsx)逐张上传图片，再以固定题位、预期版本及请求标识提交。首次发送提交后冻结草稿图片和标识；上传失败但尚未提交时仍可编辑。成功回执到达后关闭草稿并同步题位，不自动发起第二次模型任务。

提交遇到网络断开、超时或5xx时，只自动查询[保存回执](../../packages/db/src/exam-attempts.ts)，不自动重发写请求。回执单次等待最多8秒，与页面取消同时生效。查询由Cookie身份确定学生，校验题位归属，只查本人、该题位及该请求对应的run；持考试共享锁等待已有提交事务结束，不派发任务、不消耗模型额度。其他学生或题位不能读取回执。

已保存则恢复原run并同步页面；仍查不到或读取失败时保留图片，显示一次明确的恢复提示。学生点击“同步并重试”后先查回执，仍未保存才显式重试原请求与完全相同的图片；不改键绕过幂等。结果未确认前不能删图；可“返回题目”关闭草稿并重新同步，关闭本身不取消服务端可能已接收的任务。

提交本身的明确4xx拒绝不会当作已保存，版本冲突提示返回原题同步；不会把旧草稿自动套到新材料。回执查询失败不能证明提交未保存，即使查询返回4xx也保持冻结，等待主动再次同步。草稿、题号导航和题目详情各自显示当前操作错误，正文不再复制同一弹窗错误。离开页面取消本地等待并释放Blob URL，服务端已接收任务仍按原队列执行。

回执只说明请求曾被接收，不保证该run仍是最新版本或已成功答题；后续状态以当前题位快照为准。浏览器可能在连接重置时自行重传网络请求，服务端同键同内容仍只生成一个任务；不承诺物理网络包只发送一次。协议、兼容与取舍见[决策](../../.agents/notes/implemented/architecture/2026-11-05-exam-client-recovery.md)。
